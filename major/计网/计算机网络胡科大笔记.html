电路交换是什么？分组交换是什么？报文交换是什么？分组是什么？报文是什么？

电路交换：
电路交换是早起专门为电话通信服务的电信网络中使用的技术，电话交换机接通电话线的方式就是电路交换，电路交换包括三个阶段，建立连接，通话，释放连接

建立连接会从主叫方到被叫方建立一条专用的物理线路，双方通话期间双方会始终占用通信资源，通话完毕之后物理连接会被释放

但是计算机之间的通信并不能预判什么时候应该占用线路，即计算机的通信是突发的，如果采用电路交换，那么线路会被始终占用，但是发送数据的时间只占很小一部分，资源被大量浪费

分组交换：

计算机一般采用分组交换进行通信，分组交换在一个分组交换网中进行, 路由器作为分组交换网中的交换结点

通常，表示消息的整块数据称为报文，为了适应缓存容量和差错处理，一段较长的报文会被划分为较小的数据段，每个数据段前面会加上一些控制信息的首部，这就是一个个分组

发送方需要构造分组和发送分组，而转发结点的任务是缓存分组并转发分组，接收方的任务则是接收分组并还原报文

计算机网络中的速率的单位是什么？跟数据量单位有什么区别？

计算机网络中的带宽是什么？单位是什么？

带宽就是通信链路所传送数据的能力，是网络中从一点到另一点的最高数据传送率，单位和速率的单位是一样的

计算机网络中的传输，发送，传播以及各自的速率是什么？计算机方法分别是什么？

发送速率（传输速率，传送速率，或者可以说链路带宽）是指主机或路由器往（向）数字信道上发送数据的速度，也称为数据率或比特，单位是比特每秒，b/s。

传播速率是指电磁波在信道中传播的速度，单位是“米每秒”，即 m/s，更常用的是千米每秒（km/s）。电磁波在光线中的传播速率约为：2∗108m/s。

传输时延（Transmission Delay）又叫发送时延 （传送时延），是主机或路由器发送数据帧所需要的时间，也就是从数据帧的第一个比特算起，到该数据帧的最后一个比特发送完毕所需要的时间（推向信道）。计算公式：发送时延=数据帧长度/信道带宽

传播时延是电磁波在信道中传播一定的距离所花费的时间。计算公式：传播时延=信道长度/电磁波在信道上的传播速率

计算机网络中的吞吐量是什么？怎么计算的？单位是什么？

吞吐量是单位时间通过某个接口或者网络的实际数据量，计算的时候需要将上传和下载的速度加起来，单位和速率的单位也是一样的

计算机网络中的时延是什么？传输过程是什么？分为哪几个部分？分别怎么计算？

时延是指一个数据分组从网络的一段发送到另一端所需要的时间，其计算的过程直接考虑分组的最后一个 bit 即可，最后一个 bit 传播到目的主机当然就算传播完成；首先，这个分组（b）应该先通过接口到线路上，最后一个 bit 到线路上的时间就是分组的长度除以传送速率；传送的时候前面的 bit 并没有等待，这个分组是一边发送一遍传播，不过我们只考虑最后一个 bit，其被发送到线路之后就在线路上传播；接着这个分组进入路由器，需要路由器的排队和处理，因此有排队时延和处理时延；当处理好了之后路由器也应该将这个分组发送到线路上并传播到目的主机，此时我们还是只考虑最后一个 bit，再加上一个传送时延和传播时延就是最后一个 bit 到达目的主机的时延了，这里不考虑目的主机的接受时延（因为这个分组是有长度的，在线路上传播的时候同时进行接受，我们就只考虑最后一个 bit 的传送和传播，最后一个 bit 传播到目的主机当然就算传播完成，所以不考虑接受时延）

其主要由下面几个延迟组成

发送时延：
即将分组从主机传递到线路的时间，计算方式就是分组长度除以传送速率

传播时延：
传播时延仅仅与最后一个 bit 有关，最后一个 bit 到目的主机才算传播完成，而前面的数据传播与发送是并行的，所以其时延与分组长度无关，而与线路的长度和材质有关，计算方式是信道长度除以信号传播速率

排队时延：
分组在路由器缓存中的等待进入路由器和等待输出的时延

处理时延：
分组到了路由器中由路由器处理决定发送到哪里分析分组数据的时延

2 物理层

物理层是干什么的？

物理层其实不包含具体的传输媒体（光纤等），物理层主要负责的是传输媒体的接口部分，其功能包含上层信息的解码和编码，将比特流转换成传输媒体上的电信号，或者将电信号转换成比特流

定义接口标准，就是传输媒体与通信设备连接的方式是由物理层定义的

传输同步，物理层负责实现发送端和接收端的同步

选择传输介质，物理层选择传输媒体是什么，是光纤还是双绞线

可以看到，物理层其实不包含具体的传输媒体，物理层主要是接口那部分的定义等等抽象的东西

传输方式分为哪些？分别表示什么意思？

串行传输和并行传输
这个简单，不赘述

同步传输和异步传输
这里的同步和异步指的是发送方和接收方的时钟信号是否统一的意思

对于同步传输，发送方和接收方具有统一的时钟信号，同步传输发送方发送的是一串连续的比特流电信号，而接受方解释比特流电信号是在每一个信号中间采样解释的，这就要求接受方必须知道这一串比特流电信号什么时候到达和结束，否则接收方提前采样或者延后采样都会出现误差，并且接收方的接受速率也得和传送方一样，否则接收方接受比特采样的时候也会出现误差；因此同步传输一般是先有一根线进行双方的时钟同步，然后再发送比特流数据

对于异步传输，发送方和接收方没有统一的时钟信号，发送方发送单位是字节，每个字节发送方想什么时候发就什么时候发，每个字节的开头和结尾必须加上起始和结束标志位来确保接收方正确接受数据；但是每个字节内部的比特电信号速率发送方和接收方仍然是一样的，否则接收方采样也会出现错误

通信方式分为哪些？分别表示什么意思？

单向通信（单工）
类似于收音机，只能有一个方向向另一个方向传输数据

双向交替通信（半双工通信）
类似于对讲机，可以两个方向互相通信，但是不能同时传输数据

双向同时通信（全双工通信）

类似于手机打电话，两个方向可以同时互相传输数据

3 数据链路层

数据链路是什么？功能包括哪些？帧是什么？

链路是两个通信设备之间的物理线路，物理线路之间没有其他的结点

数据链路则是链路本身，以及实现数据在链路上传输所需要协议的软件和硬件，比如计算机的网卡和软件驱动程序就是数据链路层的东西（当然网卡还包括物理层的一些东西）；严格来说数据链路层并不是一个实际存在的层，而是计算机在通信的过程中会有很多的功能，将这些功能进行划分，负责某一部分功能的地方集合起来就称之为一层

数据链路层的功能包括：
（1）帧封装和解封
（2）差错检测（利用 CRC 来检测传输过程中数据是否出错）
（3）流量控制，访问控制（CSMA/CA 协议等）
（4）物理地址寻址MAC

帧是数据链路层的对等实体之间在水平之间的进行逻辑通信的协议数据单元 PDU，物理上当然是从电信号解释成比特流然后封装拆封到链路层，但是逻辑上链路层接受和发送的都是一样的东西，称为帧：

帧的封装过程是什么？

数据链路层会对上层交付的协议数据单元 PDU 添加帧首部和帧尾部，这称为封装成帧，数据链路层将帧交付给物理层，物理层将其看作比特流传输给对方

透明传输是什么？

透明传输其实就是上层给下层交付数据的时候不管下层中的规则，自己只要将数据封装好交付给下层就好了，就好像下层不存在，通信的双方对等的层直接进行通信一样

一般而言数据链路层需要对上层交付给自己的帧有所限制，比如 PDU 中不能出现标志字段，否则传输给对方的时候不知道哪里是结尾，这称为不透明传输，但是这种数据链路没有什么利用价值

透明传输是指链路层采取了某种方法解决了分不清开始结尾的问题，并对上层交付给自己的协议数据单元 PDU 没有任何限制，就好像数据链路层不存在一样（这里的意思是上层不用管数据链路层的规定，想怎么传数据给数据链路层就怎么传）

比如会在上层的 PDU 之间的标志字段前面插入转移字符，表示这个不是结束帧定界符，或者如果上层 PDU 中包含了帧定界符之后插入一些比特（HDLC 协议中的帧首部和尾部如下所示，如果 PDU 数据中有连续的五个 1 就插入一个比特 0），而接收方的数据层接受这些帧之后会去除这些比特并传给上方的网络层：

不可靠传输服务和可靠传输服务分别是什么？

不可靠传输：有误码直接丢弃

可靠传输：发送方发送什么，接收方都能正确接受，指的是必须接收到发送方发出的数据

可靠传输和不可靠传输是数据链路层对上层提供的服务，但是不局限于数据链路层，每一层向上层都会提供可靠或者不可靠的服务

一般有线链路的误码率很低不要求数据链路层向上提供可靠传输，但是无线链路层必须向上提供可靠传输服务

可靠传输的实现 - 停止等待协议（SW）的原理是什么？信道利用率怎么计算？

停止等待协议不仅仅局限于数据链路层，其基本原理是发送方发送一个数据分组，接收方接收之后发送一个确认分组，发送方受到确认分组之后再发送下一个数据分组；如果接收方检验之后发现了误码，则发送一个否认分组给发送方，于是发送方重传数据分组

加上超时重传，如果数据分组半路丢失，则接收方就不会发送什么东西，这是发送方无法判断数据分组是否发送给了接收方，因为发送方需要加上一个超时重传机制，即如果发送方经过略大于 RTT（数据链路层是这样设置的）时间没有接收到接收方的相应，则重新发送数据分组，使用超时传输之后可以不再使用否认机制

数据分组编号，如果接收方的确认分组半路丢失，那么此时发送方还是不能受到接收方的反馈，此时超时重传，发送方就会发送一个重复的数据分组给接收方，这样接收方就会出现数据分组重复的错误，因此需要对数据分组进行编号，当接收方接收到重复的数据分组后就丢弃这个重复的数据分组并重新发送一个确认分组：

接收方一定是严格按序接收的，接收方每接收一个窗口中的数据分组，则接收窗口就向前移动一个单位，如果这个数据分组丢失，则接收方会丢弃这个数据分组后面的所有分组，等到一定时间之后发送方直接超时重发

点对点 PPP 协议是什么，包括哪些东西

PPP 协议就是点对点数据链路层协议，PPP 协议其实是和以太网是两种对应的数据链路实现技术，PPP 负责点对点的数据链路通信，用于拨号上网，用于用户连接到 ISP，以及路由器之间的串行连接等等；而以太网则是用于多点通信的局域网实现技术，以太网包括物理层和数据链路层；当然以太网和 PPP 协议是可以杂糅在一起的，毕竟在多点通信的以太网中总还是有点对点通信的时候

点对点是目前使用最广泛的点对点数据链路层协议，其将上层交付下来的协议数据单元封装成帧，其包括网络控制协议 NCPs（Network Control Protocols，网络控制协议）用于支持不同的网络控制协议，以及一个链路控制协议 LCP 用于建立，配置以及测试数据链路的连接，PPP 向上提供的是不可靠传输服务：

NCPs 即网络控制协议族，其不是单单的一种协议，PPP 协议本身只负责建立点对点链路，但它并不关心上层使用什么网络协议（比如 IP、IPX 等）。为了让这些网络协议能够在 PPP 链路上运行，
PPP 引入了 NCPs。每种网络协议都有自己的 NCP，比如：IPCP（Internet Protocol Control Protocol）：用于配置 IP 协议，让自己的主机获取一个 ip 地址等等

而 LCP 协议主要负责在开始通信之前保证链路是可靠的，配置是正确的，其主要在通信开始之前配置链路，比如确定最大帧的大小，是否启用压缩，是否错误检测等等，注意这个功能是属于数据链路层的

PPP 协议的工作流程是什么？

PPP 协议的初始都是静止状态，当用户的 PC 和服务器的 ISP 之间检测到调制信号，并建立物理层的连接之后，链路就进入到建立状态，在链路建立的情况下，LCP 协议开始协商一些链路的配置，比如最大帧长和使用的鉴别协议等等，如果协商成功，则进入链路的鉴别状态，协商失败回退到静止状态

鉴别状态主要就是进行鉴别身份的，如果鉴别成功，则进入网络状态，如果鉴别失败则进入终止状态

进入网络状态之后 PPP 链路的两端开始利用特定的 NCP 协议进行 NCP 配置，比如如果链路上层使用的是 IP 协议，那么这里的 NCP 协议就是 IPCP 协议，来对链路的每一端配置 IP 地址

NCP 协议配置成功之后就进入到链路的打开状态，双方就可以进行数据通信，当链路的一端发出终止请求或出现故障的时候就进入链路的终止状态，当载波停止的时候又进入了静止状态：

MAC 地址是什么？

当多个主机连接在一个广播信道上的时候，如果想要实现两个主机之间的通信，那么每个主机必须要有一个位置的标识，即MAC 地址，也就是数据链路层地址，MAC 一般被存储在网卡的EPROM 中，因此也成为硬件地址（物理地址），这个地址是属于数据链路层的东西

一般用户的计算机有两块网卡，一个是接入有线局域网的以太网卡，一个是 WIFI 网卡，每块网卡都有一个全球唯一的 MAC 地址，交换机或者路由器有多个接口，因此也有多个 MAC 地址，MAC 地址其实就是对网络接口的唯一标识

MAC 地址的单播地址和多播地址是什么？

MAC 地址的第一字节的最后一位来区分多播还是单播，当数据帧的目的MAC 地址是多播地址的时候，那么其实设备就已经被分组了，属于这个组的所有设备都接收该帧并接受处理；当数据帧的目的MAC 地址是单播地址的时候只有一个设备会接受这个帧并处理

并且为了适应局域网的需求，MAC 帧的第一个字节的倒数第二位用来区分是全球还是本地，如果是全球的，那说明这个MAC 地址全球唯一，是从IEEE 购买的，一般我们联网的设备都有一个全球单播地址作为自己的唯一标识，如果是 0，那说明这个MAC 地址是本地管理的，用户可以任意分配：

广播地址是FF-FF-FF-FF-FF-FF，这个以太网中的所有设备都会接受这个数据帧

不同MAC 地址的作用是什么？

一般而言数据链路层在构建帧的时候会将自己的MAC 地址和目的MAC 地址构建在帧首部，比如单播的MAC 地址，这个网络上的所有设备其实都会接收到这个帧，但是如果目的MAC 地址与自己的MAC 地址不匹配，那么就会丢弃，只有匹配的帧才会被目的设备接受，而如果帧首部中是广播 MAC 地址，那么这个帧会被所有设备接受，如果是组播MAC 地址，那么只有部分设备会匹配接受

CSMA/CD 协议是什么？

这个协议是以太网采取为了处理早期总线型以太网上的总线占用问题的协议

对于总线型的以太网，某个发出的帧天然具有广播特性，即连着总线的所有设备都会接收到这个帧，但是如果有两个设备同时发送帧，那么帧就会发生碰撞问题，CSMA/CD 就是为了解决这样的问题

其原理如下：

多址接入MA：不赘述

载波监听 CS：当某个设备检测到总线空闲的时候其实总线不一定空闲，也可能是此时发送数据的设备离当前监听的设备很远，当前设备检测不到，因此还是可能出现碰撞的

碰撞检测 CD：当数据出现碰撞的时候会有碰撞信号出现，设备通过接收到碰撞信号来进行下一步的处理，当然以太网还采取了一种强化碰撞的措施，即发送帧的设备一旦检测到了总线上的碰撞，则会发送一种干扰信号，让更多的设备接收到碰撞

CSMA/CD 协议不能完全避免碰撞，并且其发送数据的时候是边检测是否碰撞边发送的，因此其就不可能同时发送和接收数据，因此这是一种半双工通信

CSMA/CA 协议是什么？

CSMA/CA 协议是 802.11 无线局域网使用的一种协议，即载波监听多址接入/碰撞避免协议

无线局域网仍然采用先听后说的方式来减少碰撞的产生，但是将碰撞检测 CD 改成了碰撞避免 CA，这里的碰撞避免是尽量避免碰撞，但是碰撞并不是可以完全避免的

无线局域网之所以采用碰撞避免的方式，是因为碰撞信号的检测在无线局域网中非常困难，除此之外哪怕硬件实现了碰撞检测，碰撞信号也很可能被屏蔽，检测将毫无意义，所以无线局域网弃用了碰撞检测，而采用了碰撞避免的技术

此外，由于无线局域网中的数据传送误码率很高，CSMA/CA 协议采用的是停止等待的确认机制来实现可靠传输

媒体接入控制方式，是数据链路层的功能之一，其的主要目标是解决多个设备在共享介质上传输数据时的冲突问题

802.11 有两种媒体接入控制方式：

分布式协调功能 DCF：

在 DCF 模式下，没有中心控制站点，每个站点使用 CSMA/CA 协议来征用信道获得发送权，DCF 模式向上提供争用服务，DCF 模式是 802.11 的默认模式

点协调模式 PCF：

PCF 方式使用集中控制方式接入算法，用类似探寻的方式把发送数据权轮流交给各个站点，从而避免了碰撞的产生

无线局域网的帧间间隔 IFS 是什么？

802.11 无线局域网规定，每个站点必须在持续检测到信道空闲一段时间后才能发送帧，这段时间称为帧间间隔 IFS，注意帧的发送不是连续的，当上一个帧发送了之后下一个帧得等待一段时间尽量避免碰撞然后再发送，这个间隔称为 IFS

帧间间隔的长短取决于站点所发送的帧的类型，一般高优先级的帧的间隔比低优先级的帧的间隔要短一些，如果低优先级的帧在将要发送的时候发现信道上还有高优先级的帧，则此时低优先级的帧继续等待

一般常用的 IFS 有两种：

（1）短帧间间隔 SIFS，长度为 28 us，其用来分开属于一次会话的两个帧，比如一个过长的 MAC 帧，以及用于回答 AP 探询的帧，这里的一次会话指的就是发送帧以及确认的传递完整数据的过程

（2）DCF 帧间隔 DIFS，其长度为 128 us，这个间隔是在 DCF 方式中使用的，用来发送数据帧和管理帧

CSMA/CA 的虚拟载波监听机制是什么？

802.11 所采用的虚拟载波监听机制，主要就是要让源站将其需要占用信道的时间通知给其他所有的站，让这段时间中的其他所有的站进行回避

具体来说，源站会在帧首部加上一个持续时间，因此某个站检测到站中传送的帧首部中的持续时间字段时，就会调整自己的网络分配向量即 NAV，NAV 指出了必须经过多长时间本次传输才能完成以及信道重新进入空闲状态

CSMA/CA 的退避机制是什么？

当站点检测到信道空闲的时候，除了等待一个 DIFS 间隔之外，还必须经过一段随机退避时间才能再次发送帧

这样做的原因是当信道空闲的时候多个站都会检测到空闲，如果各自不退避的话同时发送帧，那么就会在信道上出现碰撞

只有一种情况才会不适用退避算法：此时信道空闲，并且将要发送的帧是站点发送的第一个数据帧，除此之外的其他情况都必须使用退避算法

802.11 无线局域网的预约机制是什么？（仍然属于 CSMA/CA 协议的一部分）

这也是为了避免碰撞的一种措施，即先发送比较短的帧进行试探，如果碰撞，则执行退避算法退避一段时间后重新发送试探的帧；这样做虽然会带来额外的开销，但是如果是发送数据帧的时候发生碰撞此时重传的额外开销更大，所以采用这种机制用来避免碰撞还是可以接受的

具体来说，就是当一个站点检测到信道空闲的时候经过 DIFS 的时间间隔会先发送一个比较短的 RTS 帧，这个帧是短的控制帧，包含源地址，目的地址，本次通信所需要的时间

目的站经过 SIFS 间隔之后会发送一个 CTS 的确认帧，这个是相应 RTS 的帧，CTS 帧包含本次通信所需的时间（从 CTS 帧中复制）

原站经过一个 SIFS 间隔之后就可以发送第一个数据帧了，而其他站则是当原站收到 CTS 确认帧之后就推迟访问信道，当然，如果碰撞发生在发送 RTS 或者 CTS 帧期间，则源站会执行退避算法重传 RTS 帧

NOTE

这里的信道预约机制仍然属于虚拟载波监听机制的一部分，利用这个机制，站点只要接收到数据帧，RTS 帧，CTS 帧中的任意一个，就知道此时信道被占用，并且自己需要延迟等待，这样就可以尽可能的避免数据的碰撞

网络层的基本概念

网络层是什么？网络层的功能有哪些？

网络层主要负责将分组从源主机经过多个网络到目的主机，其主要负责分组转发和路由选择两种功能，对于一个单独的局域网，则只需要实现物理层和数据链路层就可以通信了，但是对于不同异构的网络之间的通信，则必须用到路由器，即网络层的功能

网络层向上层提供了两个服务，一个是面向连接的虚电路服务，一个是无连接的数据报服务

面向连接的虚电路服务是什么？

面向连接的虚电路是网络层提供给上层的一种服务，虚电路其实是一种逻辑上的连接，分组沿着这条连接按照存储转发的方式通信，而不是真正实际建立了一条物理连接，具体来说，分组只在连接建立的阶段使用目的主机的地址，之后分组的首部使用的就是这条虚拟连接的电路编号了，通信结束之后双方释放建立的虚电路，这种方式如果使用可靠传输的协议，那么网络自身就可以保证传递的数据准确无误

而采用电路交换的电话通信则是一条真正的物理连接，分组交换的虚电路只是与电路交换的连接类似，但是并不完全一样

无连接的数据报服务是什么？

无连接的数据报服务也是网络层向上提供的服务之一，这种方式的可靠数据通信与虚电路服务不同，其可靠性并不是由网络保证的，而是由用户主机保证

这种方式不需要建立网络连接，每个分组可以走不同的路径，并且每个分组必须携带目的主机完整的地址

这种网络服务不提供可靠的传输，保证数据的可靠依赖的是网络边缘的站点自身，那么网络内部的路由器功能就可以做得很简单，只需要负责相对简单的交付功能而不用考虑数据处理功能，这样就大大降低了路由器造价，这种方式也是现在使用最多的服务方式

网际协议，即 IP，是 TCP/IP 体系结构中的核心协议，而 TCP 则是这个结构中应用层的协议，IP 协议所在的层也称为网络层或者 IP 层，为啥这要将网际层称为 IP 层呢，这是因为网际层封装的东西大多需要封装在 IP 数据报中，具有一个 IP 首部，即 IP 协议作为了网际层大多数协议的载体，网际层的功能（一些控制信息和命令）封装在 IP 数据报中发送出去 ：

为什么要使用 IP 地址和 MAC 地址两种地址来通信呢？

这是因为 MAC 地址没有网络的划分，那么如果只用 MAC 地址，于是路由器来转发的时候就需要将海量的 MAC 地址存放到自己的路由表中，此时手工配置路由表就是不可能的，并且哪怕是自动构建路由表也需要占用海量的存储空间和资源，并且查表也是带来很大的时延

而 IP 地址由于有网络的划分，这样路由表只用存储网络号就可以了，这样路由记录就会大大减少，路由表只用记住部分网络地址，而不用记住网络中各个通信端口的 MAC 地址

简单来说 IP 地址就适用于在多个异构网络互联的时候进行大方向导航用的，而在单个局域网中将数据传给精确的主机，那就需要使用 MAC 地址了，并且在数据包传输的过程中 MAC 地址会发生变换的，这取决于每一条之间的两个结点的 MAC 地址，但是 IP 地址始终不会发生变化

一般路由器查表转发的时候是可以明确知道下一条的路由器端口的 IP 地址的，但是在数据链路层封装的时候下一条路由端口的目的 MAC 地址是无法知道的，这就需要 IP 地址解析协议 ARP 来解决这个问题

路由器的最长匹配原则是什么？

当路由器得到目的 IP 地址与路由表中的条目进行匹配的时候，首先要做的是将目的 IP 与路由表中的各个条目的地址掩码进行逻辑与运算，然后将运算结果与条目的网络地址号进行对比，看能不能对比上，即相等；

这一步的目的是假设目的 IP 在这个网络中，那么地址掩码肯定与条目的掩码相同，网络号肯定也是跟条目的网络号相同，如果假设目的 IP 在这个网络中得到的网络号与这个网络的真正网络号不一样，那肯定目的 IP 不能向这个网络转发

如果有多个条目的网络地址号可以与目的 IP 逻辑与之后的结果相等，此时我们需要选择网络地址前缀最长的那一个网络进行转发，因为网络地址前缀越长，说明这个网络越具体，转发目的 IP 的话越快转发到目的主机，比如下面这个图，对于一个最内部的目的 IP，其与外部网络的地址掩码进行逻辑与运算之后都可以相等，但是转发一定是往 172.16.10.1/32 转发，因为这个网络地址的前缀最长，最具体，最精确（这是一条特定主机路由，如果网络号与目的 IP 的相同，其优先级一定最高）

如果进行逻辑与之后发现没有一个网络地址可以与其相等，那么就向默认路由 0.0.0.0/0 转发

其实任何一个目的 IP 与默认路由的地址掩码逻辑与之后的结果都可以与默认路由网络地址相等的，只不过默认路由的前缀为 0，是最短的，只有目的 IP 逻辑与之后与其他所有的网络地址都不能相等之后才会考虑默认路由

默认路由是什么？

对于网络中的各个 ip 地址，我们其实不需要将其全部配置到路由表中，比如上图中的路由器 R 1，其就连了一个路由器 R 2，那么如果 R 1 想与除了绿色网络之外的网络通信，那肯定是要通过路由器 R 2 进行的

路由器是什么？其基本工作原理是什么？

路由器其实是一种具有多个输入输出端口的计算机，其任务就是分组转发，路由器的基本结构由路由选择部分和分组转发部分组成

路由选择部分的核心是路由选择处理机，其任务就是根据路由选择协议与其他路由器进行周期性的路由信息交换，以便构建和更新自己的路由表

分组转发部分由交换结构，一组输入端口和一组输出端口组成

信息从某个输入端口进入路由器，物理层将电信号转换成比特流之后向上交付给数据链路层，数据链路层从比特流中识别出帧，去掉帧头和帧尾向上交付给网络层处理；网络层处理数据分组，根据数据分组中的 IP 地址进行查表转发，如果没有匹配的条目，则丢弃分组；如果能够匹配，则按照匹配条目中的端口进行转发，并且网络层会修改数据分组中的一些值，比如将 TTL 减一，首部检验和等字段，然后交给数据链路层进行封装，数据链路层将数据分组封装成帧之后交给物理层，物理层将帧看作比特流，变换成电信号发送出去

输入缓存区用来处理新进入路由器但是还没有来得及处理的分组，输出缓冲区用来暂存已经处理完毕但是还来不及发送的分组，一般路由器的端口同时具有输入和输出的功能

（2）利用剪枝算法，剪除广播转发树的下游成员，最后获得一个多播转发树

RPB 算法建立广播转发树的原理是什么？

对于一个广播转发树，其实可以采用洪泛的做法建立，但是一旦网络中存在环路，则会出现永久兜圈的问题：

RPB 算法就是为了解决这种兜圈问题，其基本原理为：

（1）当本路由器收到一个广播分组时，先检查这个广播分组是否从自己距离源点的最短路径上传过来的，即将广播分组传递给自己的上一个路由器是否在本路由器距离源点的最短路径上

（2）如果这个广播分组是从位于本路由器和源点的最短路径上的路由器转发过来的，则将这个广播分组向本路由器的所有接口转发，如果不是则丢弃这个分组

（3）如果本路由器收到多个广播分组均来自位于本路由器和源点的最短路径上的路由器转发（即帧路由器到源点的最短距离不止一条），则选取接受 IP 地址最小的那个路由器转发给自己的广播分组，其他的广播分组则丢弃

（1）简单来说就是在每一个多播组中指定一个核心路由器，以这个路由器为根，建立一颗连接多播组的所有成员路由器的生成树，这棵树就是多播转发树

软件定义网络 SDN

软件定义网络的基本概念是什么？

在传统网络中路由器有两个基本功能，一个是为主机之间的通信转发分组，一个是进行路由选择，路由选择是用来决定往哪里转发分组路径最短的属于控制的功能，而转发分组则直接进行数据处理，属于数据的功能；因此路由器之间交互的信息也可以分为两类，一类是主机之间的分组，一类是交换的路由信息

路由器根据路由信息利用路由算法得到路由表，再根据路由表得到分组的转发表，这样就可以将路由器分为两个层面，一个是控制层面，主要用来控制分组从哪里走时间更短；一个是数据层面，用来之间转发分组和处理分组数据：

路由器的控制层面是通过与相邻的路由器交换路由信息，由软件计算得到的，这需要花费较多的时间

而 SDN 则是将这些路由器的控制层面全部剪除，所有的路由器不再互相交换路由信息了，而由一个远程的控制器统一调度所有的路由器

远程控制器可以掌握整个网络的状态，为每一个分组计算最佳的路由，为每个路由器生成正确的转发表，那么路由器只用查表转发就好了，所以 SDN 的核心思想就是将网络中的控制层面和数据层面分离，用远程的软件来控制网络中的各个设备

（1）基于流的转发

（3）位于数据层面之外的分组交换机的网络控制功能

物理层，数据链路层，网络层这三个层面共同完成了主机通过异构网络之间进行的通信，即主机和主机之间的通信

运输层向应用层屏蔽了网络的具体细节，即网络层不需要管下面层级的结构或者信息，只用将自己的信息交给运输层就好了，这样在网络层看来就好像运输层之间有一条端到端的通信链路一样，这个称为逻辑通信信道，但实际上运输层还是一层层往下封装，然后再一层层网上拆封得到信息的

这里每个层级之间的逻辑通信也是这样理解的，比如网络层看数据链路层，网络层不用在意物理层的存在，只需要将信息交付给数据链路层，在网络层看来两个对等主机的数据链路层就好像有一个信道连接一样，这个就称为对等实体之间的逻辑通信

运输层给应用层提供了两种不同的运输层协议，一种是面向连接的 TCP 协议，一种是无连接的 UDP 协议

对于网络的应用层的各个协议，有的协议需要使用可靠的传输，比如 HTTP 和 SMTP，有的协议不需要可靠的传输，比如 DNS，RTP；这些协议的内容到达网络层都是要用 IP 数据报进行封装的，而 IP 数据报在网络层传输时统一提供的是不可靠的传输，所以当 IP 数据报交付到站点时，运输层的就应该保证传输的可靠或者不可靠

运输层的端口号是什么？

端口号其实不是一个实际的端口，而是运输层区分应用层进程的标识号，即应用层的应用进程标识 PID会实际映射到运输层一个端口号，端口号其实更像是一种封装的概念，应用层的进程只用取监听运输层中某个端口号的信息，而不用分析运输层的所有信息从中找到发给自己的

为啥运输层不直接用 PID 来区分进程，而是用端口号来区分呢？

进程 PID 与操作系统深度绑定，应用进程重启或者发生什么变化进程 PID 都会发生变化，那此时正在网络中传递的数据报又知道该传给哪个进程呢？此时显然会影响网络上的通信，而一般服务器的一个固定的应用进程会持续监听一个固定的端口号，比如 HTTP 应用进程持续监听端口号 80，哪怕进程的 PID 发生变化，这个进程也是从 80 接收数据，不影响网络的数据封装和通信

这个思想也有点像面向对象的封装思想，将应用层进程和运输层分开，应用层出现变化的时候不影响运输层接收数据

运输层的端口号的分类有哪些？

（1）短暂端口号虽然是通信的过程中临时分配的，但是在通信过程中其实是不变的，通信过程中哪怕进程 pid 改变端口号也是不变的，即这个进程在通信过程中监听端口号是不变的，这样仍然可以保证通信的连续性

（2）每个主机的端口号都是独立的，各个计算机之间端口号没有联系，哪怕两个主机的两个独立的通信过程中端口号因为巧合用一样的，那也没有什么联系

发送方的复用和接收方的分用是什么？

所谓复用，其实就是发送方封装的意思，发送方的报文在运输层用 UDP 协议进行封装，称为 UDP 复用，使用 TCP 协议进行封装，称为 TCP 复用；在网络层用 IP 协议进行封装，称为 IP 复用

所谓分用，其实就是接收方拆分对应的协议数据报向上交付的意思，接收方接收到 IP 数据报之后根据 IP 首部的协议字段向上交付给运输层的 UDP 或者 TCP 协议，这个阶段称为 IP 分用；接收方的运输层根据 UDP 数据报或者 TCP 数据报首部中的端口号向上交付给对应的进程，这个称为 UDP 的分用或者 TCP 的分用：

UDP 和 TCP 对单播多播广播的支持情况有哪些区别？

UDP 支持单播，多播，广播，即 UDP 支持一对一，一对多，一对全的通信

使用 TCP 协议的双方在通信之前必须三次握手建立连接，这样两者之间就好像有一个可靠的通信通道一样，双方就基于这个逻辑信道通信，TCP 只支持一对一的通信：

UDP 和 TCP 对应用层报文的处理有什么区别？

UDP 对上层交付的应用层报文，既不合并也不拆分，保留这些应用层报文的边界，自己仅仅加上一个 UDP 的首部，而接收方的 UDP 仅仅将 UDP 首部拆掉向上交付，即 UDP 是面向应用层报文的

而 TCP 则将应用层的报文看作字节序列，将这些字节序列缓存在自己的发送缓存中，TCP 根据自己的发送策略，从缓存中提取一定的字节添加一个首部从而构建 TCP 报文发送，接收方的 TCP 一方面将接收的 TCP 报文中的数据载荷字节存放在自己的接收缓存中，一方面向上交付字节；应用层使用 TCP 协议的应用进程必须有能力将字节流还原成自己的报文数据；总的来说 TCP 是面向字节流的

UDP 和 TCP 对数据传输可靠性的支持情况是什么？

UDP 向上层提供的是无连接不可靠的传输服务，即 UDP 数据报如果在传输中出现了误码或者被路由器丢失，发送方是不会采取什么措施的；因此 UDP 协议一般用于视频，音频等实时应用

TCP 协议尽管也是使用网络层的不可靠传输协议 IP，但是收发双方可以基于 TCP 连接的可靠信道进行数据传输，不会出现误码，丢失，乱序等情况，也就是说虽然网络层的 IP 数据报在交付的过程中不会进行差错处理，但是交付给上层的运输层的 TCP 协议时，运输层的 TCP 协议会进行各种差错处理，利用建立的逻辑信道强迫发送方发送正确数据过来；

NOTE

比如你网络层将一个误码的数据交付给了接收方的运输层 TCP 协议，TCP 协议发现了误码，则会封装错误信息给网络层，网络层同样是将这个报文封装在 IP 协议中，然后传回发送方，让发送方知道自己之前的发送数据有误了，然后重新发送（这只是一种理解 TCP 提供可靠传输和 IP 提供不可靠传输的一种方式，实际可能更复杂）

总的来说 IP 数据报就是一个信息传输载体，TCP 协议会将控制信息，差错信息向下封装在这个载体中传送给发送方互相控制发送数据的正确性

TCP 一般用于文件传输等对实时性要求不高，但是对准确性要求高的场合

UDP 和 TCP 两个协议的首部有哪些区别？

UDP 的首部非常简单，只添加了用于区分应用层进程的端口

而 TCP 的首部非常复杂，其要实现很多功能，流量控制，拥塞控制等等

TCP 三次握手（三报文握手）建立连接的过程是什么？

这里举一个例子来说明，首先连接的双方有一方主动请求建立连接称为 TCP 客户，另一台主机被动等待 TCP 连接的应用进程，称为 TCP 服务器

TCP 握手需要在 TCP 客户和 TCP 服务器之间建立三个报文段

TCP 服务器需要首先建立一个传输控制块 TCB，用来存储 TCP 连接中的一些重要信息，然后 TCP 服务器就进入监听状态，等待 TCP 客户端的连接请求（这个称为被动打开连接）：

TCP 客户端也会建立一个传输控制块

然后就开始正式三次握手了

（1）TCP 客户端发送一个 TCP 连接请求报文段，进入同步已发送状态，这个请求报文段中的 SYN 设置为 1 表示这是一个 TCP 连接请求报文段，这个请求报文段首部的序号字段被设置了一个初始值 x，注意 SYN = 1 的报文段不能携带数据，但是还是需要消耗一个序号，根据 TCP 报文段的序号设置原则，TCP 客户端下一次报文的数据载荷的第一个字节序号就是 x + 1;这个过程称为主动打开连接

（2）TCP 服务器接收到客户端的请求报文之后，如果同意请求，则向客户端发送连接请求确认报文段，并进入同步已接受状态，这个报文的同步标志位 SYN = 1 确认标志位ACK = 1，表示这是一个连接请求确认报文段；TCP 报文首部中的序号字段被设置为 y，这个是服务器随意选择的一个初试序号；注意这里 SYN = 1，TCP 报文仍然不携带数据，这里的序号只是服务器选择并消耗的；首部中的确认号 ack = x + 1，表示服务器对客户端发过来的序号 x 接收成功，期望接收序号 x + 1 的数据

（3）客户端接收到服务器的连接确认报文字段之后，还要针对这个服务器发送的 TCP 连接确认报文段向服务器发送一个普通的 TCP 确认报文段（这个普通报文字段可以封装一些实际信息了，比如 HTTP 请求报文可以封装在其中）

NOTE

此时 SYN 字段的值不再是 1 注意只有连接请求报文和连接请求确认报文的 SYN 才等于 1

然后进入连接已建立状态；这个普通的 TCP 确认报文的 ACK = 1，表明这是一个普通的 TCP 确认报文，这个确认报文的序号字段是 x + 1

NOTE

这是因为上次自己发送的序号 = x 的报文已经被服务器接收，服务器的连接确认报文中的确认序号 = x + 1，表面服务器想要接收 x + 1 的序号数据，因此这里的客户端的普通确认报文的序号就是 x + 1，注意这里的普通确认报文也可以不携带数据，当不携带数据的时候这里不消耗序号，那么客户端下一次发送的报文的序号仍然是 x + 1

这个普通确认报文中的确认序号 ack = y + 1，表明是对服务器的连接确认报文序号 seq = y 的确认

这三个报文发送之后，TCP 双方都进入连接已建立状态，此时他们就可以基于已建立好的 TCP 连接进行可靠数据传输了：

为什么三次握手中还需要最后一次握手？两次握手不行吗？

不行，因为假如客户端的连接请求报文超时到达服务器就会出现问题

如果改为两次握手，那么服务器收到客户的连接请求报文然后发送连接请求确认报文之后服务器就直接进入了连接建立状态；

TCP 的流量控制是什么？

TCP 的客户端和服务器端都即可以作为发送方，也可以作为接收方，因此两者既有接收缓存，又有发送缓存，这里假设 TCP 客户端作为发送方

客户端和服务器端建立连接之后，TCP 的客户端的运输层将应用层的报文看作字节序列存入发送缓存中，并根据发送策略取出一定的字节封装成 TCP 报文段之后进行发送

TCP 接收方接收到发送方的报文段之后将其放入接收缓存暂存，响应的应用程序会从该接收缓存中读取数据

流量控制与拥塞控制的区别是什么？

流量控制是确保发送方不会持续以超过接收方接收能力的速率发送数据，以防止接收方来不及从接收缓存中取走数据而导致接收缓存溢出从而数据丢失

而拥塞控制是防止过多的数据注入到网络中，使网络能够承受现有的网络负荷

拥塞控制和流量控制都需要控制源点的数据发送速率，但是流量控制是点对点的控制，是接收方根据自己的接收能力控制发送方的速率

但是拥塞控制是源点根据各种因素自己按照算法控制发送速率，源点考虑的是全局问题，包括各种路由器，主机等等

简单来说，拥塞控制是源点根据整个网络的情况来调整自己的发送速率，而流量控制则是源点根据接收方的反馈来调整自己的发送速率

DHCP 是应用层的协议，其使用运输层中的 UDP 作为载体，在运输层被封装为 UDP 报文，DHCP 服务进程使用的端口默认是 67；DHCP 客户使用的默认端口是 68

封装 DHCP 协议的 UDP 报文在网络层被封装为 IP 数据包，然后在数据链路层被封装为数据帧发送

在最开始的时候主机向网络中广播 DHCP 发现报文，源 IP 地址为 0.0.0.0，因为此时主机还没有自己的网络配置信息，目的地址为广播地址，之所以要广播，是因为主机并不知道网络中有哪些服务器，DHCP 发现报文中封装有 DHCP 客户端的 MAC 地址，和此次 DHCP 服务的事物 ID:

对于非 DHCP 主机，其没有持续监听 67 端口的进程，所以会丢弃这个数据报，但是对于 DHCP 服务器，其 DHCP 应用进程始终监听这个端口所以会接受这个报文并做出响应

DHCP 服务器会根据发现报文中客户的 MAC 地址来查找自己的数据库，看是否有这个客户的配置信息，如果有，则使用这个信息来构建 DHCP 提供报文，如果没有，则使用默认配置信息构建报文

DHCP 服务器发送 DHCP 提供报文的时候仍然使用的是广播地址，这是因为源主机现在还是没有 IP 地址，此时网络中的所有主机都会收到这个报文，但是只有运行 DHCP 应用进程的客户才会在运输层监听这个 68 号端口并接收

此时客户会根据 DHCP 提供报文中的事物 ID 判断是否是属于自己请求事物，如果是则接受，否则丢弃，然后收到 DHCP 提供报文中的配置信息，DHCP 客户会接受先到达的 DHCP 提供报文，需要注意的是服务器在封装 DHCP 报文的时候会利用 ARP 协议判断哪些 IP 地址被使用了，然后将空闲的 IP 分配给主机：

这个 DHCP 请求报文的源地址还是 0.0.0.0，因为其没有向 DHCP 服务器征得同意使用配置信息呢，目的 IP 地址是广播地址，这样客户端只用发送一次即可，网络中的所有 DHCP 服务器都会收到这个报文，这个报文中封装了此次 DHCP 服务的事物 ID，客户端自己的 MAC 地址，以及客户端接受的服务器的 IP 地址和所接受的服务器提供的 IP 地址：

当租用期到了一半的时候，客户端还会向 DHCP 服务器发送请求报文来更新租用期，这个报文的源 IP 就是 DHCP 客户端租用的 IP 地址，目的地址就是 DHCP 服务器地址，DHCP 服务器如果同意，则会发送确认报文，这样客户端就得到了更新租用时间的 IP 地址，如果 DHCP 服务器不同意，那么客户端就给停止使用这个 IP 地址，并必须重新发送 DHCP 发现报文来申请 IP 地址

然后发送方 A 将带有数字签名的报文发送给接收方，接收方用公钥来核实数字签名，即用公钥对收到的带有数字签名的数据进行加密运算，这样就可以得到原来的报文

由于 A 的私钥只有 A 知道，所以没有人可以产生 Dska (m)，只要这个数据在传输过程中被篡改，那么接收方就不可能通过公钥加密得到一个可读的报文，这样也就保证了 DSKA (m) 只能是由 A 发送的，并且谁也不能伪造

此外，如果 A 不承认报文是由其发送的，但是由于公钥和加密算法是公开的，接收方可以让第三方对 A 发送的 DSKA (m) 进行验证，这样 A 就不可能赖账

这样，数字签名就实现了对报文来源的鉴别，但是一般情况不是对整个报文进行数字签名，而是仅仅对报文的摘要进行，顺便进行报文的鉴别

保密性的数字签名是什么？

上文中数字签名的过程，很显然仅仅可以证实报文的来源，但是对报文本身没有加密，攻击者可以很容易还原出来 A 发送的报文

其原理为，当 A 通过自己的私钥通过解密算法得到 Dska (m) 之后，同时利用 B 的公钥对其加密得到 Epkb (Dska (m))

接收方 B 收到之后首先用自己的私钥对 Epkb (Dska (m)) 解密得到 Dska (m)，即带有数字签名的 m，接着用 A 的公钥对数字签名使用加密算法，这样就得到原来的报文 m 了

这样就实现了对报文的签名（A 用私钥解密，B 用公钥加密），同时还对报文进行了保密（A 用公钥对签名后的报文加密，B 用私钥解密）

不重数是什么？

不重数其实就是为了应对重放攻击而设计的手段

简单来说就是通信双方共享一个密钥，然后通信双方分别选择两个随机数

首先 A 先将用户名和自己的随机数发送给 B

B 利用共享的密钥加密 A 的随机数，并将自己的随机数发送给 A，A 收到之后利用共享密钥解密 B 发过来的对自己随机数的加密，这样来验证 B 的身份

同时 A 还要将 B 发给自己的随机数 RB 加密发送给 B，这样 B 可以利用共享的密钥还原出自己的随机数，这样 B 就验证了 A 的身份

验证了双方身份之后就可以进行通信了

这种方式的好处在于，每次会话 A 和 B 的随机数都是变换的，不会都一样，但是攻击者不能做到每次都截获，其截获一次得到的随机数不能重复使用，当通信双方变了一个随机数之后攻击者就不能伪造身份获得数据了（其实攻击者哪怕截获之后也要不停转发才能获得数据，并且在截获的时候双方通信都得截获才能验证身份，这样代价也会高很多）

并且攻击者不能直接伪装自己就是 A 与 B 进行通信，因为攻击者是没有私钥的，不能通过实体鉴别

使用公钥密码体制进行不重数实体鉴别方法是什么？

发送方和接收方 A 和 B 两者都随机挑选了一个随机数 RA 和 RB

首先，A 将自己的用户名和随机数 RA 发送给接收者 B，B 收到 RA 之后利用自己的私钥对 RA 进行加密签名得到 SKB (RA)

然后 B 将自己的随机数和 SKB (RA) 发送给 A，A 收到之后利用公钥解密核实出 RA，于是就验证了 B 的身份

同时 A 利用自己的私钥对 B 发过来的 RB 进行加密数字签名发送给 B，B 利用公钥解密验证 SKA (RB)，这样就验证了 A 的身份

后退 N 帧的意思就是如果发送方发送的某个数据帧丢失，接收方没有收到，不会发送对这个帧的确认，那么发送方会将该帧以及该帧之后的 N 个数据帧重新发送出去（出错的帧以及之后的 N 帧全部重传）

接收方会反复发送对 3 号帧的确认，这个帧是接收方最后一个确认帧，并丢弃 5 和 6 号帧

接收方发送的对 3 号帧的确认并不是发送方重新发送的信号，发送方只有等到计时器到时之后才会重新发送 4 号帧以及之后的帧

GBN 协议中决定发送方重传帧的机制是什么？发送方是怎么重传的？重传的是哪些帧？

决定重传的机制是计时器到时，发送方等到 4 号帧的计时器到时之后会重传 4 号帧以及之后的帧

GBN 接收方的累计确认是指什么？接收方发送一个确认帧表示哪些帧得到确认？接收方接收到编号 4 5 6 帧发送的是那个帧的确认？

接收方只发送对数据帧 6 的确认

GBN 发送方的累计确认是指什么？

GBN 协议中的发送窗口大小和接收窗口大小有什么规定？

接收窗口大小是 1

发送窗口大小是 1<Wt​≤2i−1，这里的 i 是给数据帧进行编号的比特数

GBN 协议中，如果用 3 bit 编号，并且发送窗口过大，为 8，则此时会出现什么错误情况？这种窗口大小为什么不行？

发送方发送的一连串帧是 0 1 2 3 4 5 6 7，此时发送方窗口中的帧就是这些

假如 0 号帧丢失，那么接收方会发送最后接收的一个帧的确认帧，也就是上一轮的 7 号帧的确认，但是这个是上一轮的老的 7 号帧的确认，而当接收方接收到这个帧之后会误以为对本次发送的 7 号帧的确认，发送方就会后移它的窗口，但是对于接收方来说实际上这 8 个数据帧全部都没有收到，导致数据丢失

可靠传输机制 - SR 协议

选择重传协议 SR 正常工作的时候的过程是什么？

选择重传协议 SR 相对 GBN 的改进在哪里？

SR 协议只会重传出现差错的帧，而不是窗口中所有的帧全部重传

并且去掉了累计确认改为逐帧确认

SR 协议在遇到 0 1 2 3 号帧，2 3 正确接收，0 中途丢失，1 接收后出现错误，此时的工作过程是什么？

2 3 正确接收，接收方发送 2 3 的 ACK 帧

1 出错，接收方直接丢弃这个帧并发送一个 NAK 帧，要求发送方立刻重传 1 号帧

发送方收到 NAK 帧会立刻重传这个帧，而对于 0 号帧则是等到计时器到时则重传这个帧

选择重传协议采用的确认规则是什么？

SR 协议采用的是逐帧确认的方式

SR 协议中发送窗口和接收窗口的大小规定是什么？

（1）接收窗口 Wr 和发送窗口 Wt 大小都大于 1

（2）Wr+Wt<=2n，这里的 n 是给数据帧编号的比特数

（3）Wr<=Wt

（4）根据（2）和（3）得到 Wr<=2n−1

SR 协议中，当 3 bit 进行帧编号，发送方和接收方采用的窗口大小是 5 的时候会出现什么问题？

发送方会发送 0 1 2 3 4 给接收方

假设接收方正确接收，并返回这 5 个帧的确认

但是 0 号确认帧在过程中丢失：

那么发送方会一直重传 0 号帧，而由于接收方此前已经接收到了旧的 0 1 2 3 4 帧，窗口已经滑动了，此时再接收到 0 号帧，那么它就会误认为这个 0 号帧是新窗口中的 0 号帧，那么接收方就会收下这个 0 号帧，那么下次发送方真正发送这个 0 号帧的时候接收方就会直接丢弃它，导致帧丢失
