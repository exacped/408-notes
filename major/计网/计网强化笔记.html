归零编码

这里由于每个码元中间都归零，所以就像节拍器一样可以打拍子，所以可以实现自同步机制，双方可以通过跳变来知道时钟信号

这里双方不能利用单纯的数据电平来知道时钟信号，因为这里连续的 0 和连续的 1 的电平并不会发生改变，你这里并不能通过跳变知道一个时钟信号有多长，比如上图 0 1 0 的信号，这里虽然从 0 到 1 再从 1 到 0 跳变了两次，但是接收方不知道时钟信号，它可能认为这两个 0 之间有多个连续的1，接收方可能认为时钟信号比发送方知道的时钟信号更短

意思是一个码元可以表示 k 种不同的二进制编码（k 种不同的状态），比如 2 进制码元，那一个码元就可以表示 2 种二进制编码，那一个码元就携带一个比特就可以了

k 进制码元就是一个码元有 k 个不同的离散值

透明传输是什么？

这里透明传输是指数据链路层不对上层交付给自己的数据做任何限制，也就是在上一层（网络层）看来，我不管交给什么给数据链路层都是可以的，就好像数据链路层不存在一样，这个就是透明传输

透明传输主要是解决这样的问题，数据链路层会对上层 PDU 进行封装，如果上层 PDU 内部有数据链路层封装的开头和起始字段，那就会出错，为了实现透明传输，即数据链路层不应该让上层来处理这个问题，上层不应该为了考虑数据链路层而对自己的 PDU 进行某些限制，数据链路层本身应该解决这个问题，字符填充法和比特填充法就是数据链路层解决这个问题的两种方法

以太网帧是如何实现透明传输的？（以太网如何进行帧定界）

以太网其实不存在透明传输的问题，数据链路层本身不需要进行什么处理，数据链路层交付给下层物理层，物理层会加上前导码来进行帧定界

前导码包括 7 B 的前同步码和 1 B 的帧开始符

以太网还规定了帧间间隔时间为 96 bit 时间用来帧定界

字节填充法怎么实现透明传输？

（1）在帧的首部和尾部加上帧定界符
（2）如果内部的数据载荷出现帧定界符，则在其前面加上 ESC 转义字符
（3）如果内部数据载荷出现转义字符 ESC，则在其前面再加上转移字符 ESC
（4）接收方接收的时候需要删除发送方在数据载荷中插入的转移字符 ESC

0 比特填充法如何实现透明传输？

（1）开头和结尾加上 0111 1110 用于帧定界
（2）数据载荷内部如果出现连续的 5 个 1 则加一个 0
（3）接收方扫描数据载荷，当发现连续的 5 个 1 时就删除后面的一个 0

SW 协议，GBN 协议，SR 协议三种 ARQ 协议的窗口大小分别是什么？

（1）SW 协议 Wt = 1，WR= 1
（2）三种协议发送窗口和接收窗口应该满足 Wt​+WR​≤2n，n 是序号使用的比特数
（3）GBN 协议接收窗口是 1，因此发送窗口的范围就是 1<Wt​≤2n−1
（4）SR 协议的发送窗口应该比接收窗口大，即 1<WR​≤Wt​
（5）SR 协议接收窗口取 2 的时候发送窗口可以取最大，即 1<Wt​≤2n−2
（6）SR 协议接收窗口取 2n−1 的时候发送窗口只能为 2n−1 了
（7）SR 协议的发送窗口与接收窗口一般都是相等的，所以发送窗口就是 2n−1

对于选择重传来说，Wr 是接收窗口，Wt 是发送窗口

（1）发送窗口应该大于等于接收窗口，否则接收窗口一直接收不满，这会造成浪费，同时由于是选择重传，所以两个窗口的大小应该和 SW 和 GBN 区分开，所以 Wt >= Wr > 1
（2）Wt 和 Wr 的共同约束是 Wt + Wr <= 2^n
（3）因此对于接收窗口 Wr 来说，它的范围是 1<Wr≤2n−1，它不可能再大，再大的话发送窗口就小于接收窗口了，这样造成浪费
（4）因此对于发送窗口来说，它的范围是 1<Wt​≤2n−2，当接收窗口取 2 的时候发送窗口可以取最大
（5）当接收窗口取 2n−1 的时候，发送窗口只能取 2n−1 了

所以对于 SR 协议需要记住下面 5 个公式：
（1）1<Wr≤Wt
（2）Wr+Wt≤2n
（3）1<Wr≤2n−1
（4）1<Wt≤2n−2
（5）Wr=2n−1 的时候 Wt=2n−1

滑动窗口的序号发送和接收情况是什么？

（2）接收方每正确收到一个落入接收窗口的数据分组，才能将窗口划过这个帧

1-坚持 CSMA；p-坚持 CSMA；非坚持 CSMA 协议分别是什么？

（1）非坚持：信道空闲则发送，信道忙则放弃坚持监听，随机等待一段时间再监听；延迟高，碰撞低
（2）1-坚持：信道空闲则发送，信道忙则一直坚持监听，信道空闲则立刻发送：延迟低，碰撞高
（3）p-坚持：信道空闲则概率 p 发送，概率 1-p 推迟发送，等待一段时间重新监听；信道忙则一直监听信道，直到信道空闲进入概率发送阶段

点对点是目前使用最广泛的点对点数据链路层协议，其将上层交付下来的协议数据单元封装成帧，其包括网络控制协议 NCPs（Network Control Protocols，网络控制协议）用于支持不同的网络控制协议，以及一个链路控制协议 LCP 用于建立，配置以及测试数据链路的连接，PPP 向上提供的是不可靠传输服务：

而 LCP 协议主要负责在开始通信之前保证链路是可靠的，配置是正确的，其主要在通信开始之前配置链路，比如确定最大帧的大小，是否启用压缩，是否错误检测等等，注意这个功能是属于数据链路层的

PPP 协议的工作流程是什么？

PPP 协议的初始都是静止状态，当用户的 PC 和服务器的 ISP 之间检测到调制信号，并建立物理层的连接之后（拉一根网线），链路就进入到建立状态，在链路建立的情况下，LCP 协议（PPP 协议的组成部分之一）开始协商一些链路的配置，比如最大帧长和使用的鉴别协议等等，如果协商成功，则进入链路的鉴别状态，协商失败回退到静止状态

鉴别状态主要就是进行鉴别身份的，如果鉴别成功，则进入网络状态，如果鉴别失败则进入终止状态

进入网络状态之后 PPP 链路的两端开始利用特定的 NCP 协议（PPP 协议的组成部分之一）进行 NCP 配置，比如如果链路上层使用的是 IP 协议，那么这里的 NCP 协议就是 IPCP 协议，来对链路的每一端配置 IP 地址

NCP 协议配置成功之后就进入到链路的打开状态，双方就可以进行数据通信，当链路的一端发出终止请求或出现故障的时候就进入链路的终止状态，当载波停止的时候又进入了静止状态：

网络层主要负责将分组从源主机经过多个网络到目的主机，其主要负责分组转发和路由选择两种功能，对于一个单独的局域网，则只需要实现物理层和数据链路层就可以通信了，但是对于不同异构的网络之间的通信，则必须用到路由器，即网络层的功能

面向连接的虚电路服务是什么？

面向连接的虚电路是网络层提供给上层的一种服务，虚电路其实是一种逻辑上的连接，分组沿着这条连接按照存储转发的方式通信，而不是真正实际建立了一条物理连接，具体来说，分组只在连接建立的阶段使用目的主机的地址，之后分组的首部使用的就是这条虚拟连接的电路编号了，通信结束之后双方释放建立的虚电路，这种方式如果使用可靠传输的协议，那么网络自身就可以保证传递的数据准确无误

而采用电路交换的电话通信则是一条真正的物理连接，分组交换的虚电路只是与电路交换的连接类似，但是并不完全一样

无连接的数据报服务是什么？

无连接的数据报服务也是网络层向上提供的服务之一，这种方式的可靠数据通信与虚电路服务不同，其可靠性并不是由网络保证的，而是由用户主机保证

这种方式不需要建立网络连接，每个分组可以走不同的路径，并且每个分组必须携带目的主机完整的地址

这种网络服务不提供可靠的传输，保证数据的可靠依赖的是网络边缘的站点自身，那么网络内部的路由器功能就可以做得很简单，只需要负责相对简单的交付功能而不用考虑数据处理功能，这样就大大降低了路由器造价，这种方式也是现在使用最多的服务方式

而我们自己进行子网划分的时候是将网络全部分割开的，所以不能有某个子网是另一个子网的前缀的情况出现，否则就会出现 IP 重复，那么根据最长匹配规则，就可能出现转发错误

地址解析协议 ARP 是什么？其工作过程是什么？

（1）有一个表记录 IP 和 MAC 地址对应关系
（2）如果源主机 A 不知道目的主机 B 的 MAC 地址，则广播
（3）B 收到之后，记录 A 的 IP 和 A 的 MAC 关系，同时回应自己的 MAC
（4）A 收到 B 的 MAC 之后在在即的表中记录 B 的 IP 和 MAC 对应关系

arp 请求报文

源 IP：发起请求的主机 IP
目的 IP：目的主机 IP
源 MAC：发起主机的 MAC
目的 mAC: FF-FF-FF-FF-FF-FF

ARP 响应报文

源 IP：被请求的主机 IP
目的 IP: 发起请求的主机 IP
源 MAC：被请求主机的 MAC
目的 MAC: 发起请求主机的 MAC

ARP 请求和响应报文中，其实只有 arp 请求的目的 MAC 是广播地址，其他的地址都不是广播地址

主机想要转发数据给不同的局域网的主机，ARP 协议是如何工作的？

（1）主机 A 通过 IP 地址对比发现转交的目的主机根自己不再同一个网络
（2）则通过 ARP 协议找到这个局域网的路由器 MAC，让路由器转交

ARP 使用的前提就是同一个局域网中的主机以及路由器是知道彼此之间的 IP 地址的

局域网 1 中的主机 A 想要给局域网 3 中的主机 B 发送 IP 数据报，但是局域网 1 的主机只知道局域网 3 的主机 B 的 IP 地址，MAC 地址啥的完全不知道，那么主机 A 得通过路由器 R 1 进行转发这个数据报

在主机 A 不知道 R 1 （路由器 1）的 MAC 地址的情况下，主机 A 会通过 R 1 的 IP 和 ARP 协议找到 R 1 的 MAC 地址，然后将 IP 数据报转交给 R 1

R 1 会通过 ARP 协议找到路由器 R 2 的 MAC 地址，然后将 IP 数据报转交给 R 2

R 2 再根据 ARP 协议找到主机 B 的 MAC 地址，然后将 IP 数据报转交主机 B，这个过程才算结束

这个过程就是间接交付的过程了

记住几个规定

（1）以太网规定的 MTU，即 IP 的首部加上数据部分的最大长度不超过 1500 B（这是默认情况，如果题目有交代则以题目为准）
（2）IP 数据报的首部是 20 B，因此根据 MTU，IP 数据报的数据部分最大就是 1480 B
（3）由于片偏移是以 8 B 为单位，所以每个 IP 数据报的数据部分的最大长度必须是 8 的整数倍，这里并不要求 IP 数据报的数据部分没填满的时候是 8 的整数倍字节数，这里要求满足 MTU 的 IP 数据报的数据部分最大长度是 8 的倍数，因为只有这样，第二个分片之后的分片的片偏移才能填有效数字

计算思路

（1）得到初始的 IP 数据报的数据部分 DATA
（2）根据以太网的 MTU 得到数据部分可划分的最大长度 LEN
（3）DATA 就根据 LEN 来进行划分，按照尽可能大，并且是 8 的倍数来进行分片
（4）最后每个分片加上 20 B 的 IP 固定首部

路由选择协议-OSPF

OSPF 协议是什么？特点（3 个）

OSPF 是为了克服 RIP 协议的缺点而被开发出来的，开放指的是这个协议是公开发表的，最短路径优先是指这个协议使用了 Dijkstra 算法来计算最短路，OSPF 就是采用了最短路算法基于链路状态来计算最短路径的协议

（1）OSPF 基于链路状态
（2）OSPF 基于最短路算法计算路径
（3）OSPF 不限制网络规模

OSPF 协议中的链路状态是指什么？

相连了哪些路由器，以及相邻路由器之间的链路代价，由网络管理人员决定

OSPF 是如何维护邻居关系的？

（1）通过封装在 IP 协议中的 HELLO 分组来维护邻居关系
（2）HELLO 分组的发送周期是 10 s，如果 40 s 没有收到邻居的 HELLO 分组，则认为不可达
（3）每个路由器还有一个邻居表

OSPF 中的路由器 ID 是什么？

（1）一个 32 bit 的无符号整数，格式与 IP 地址相同，用来唯一标识一台机器

OSPF 协议中的链路状态通告 LSA 是什么？

（1）用来报告一些链路信息
（2）包括相邻路由器链路和相邻网络链路

OSPF 协议中的链路状态更新分组 LSU 是什么？

（1）LSU 分组是用来封装 LSA 的
（2）LSU 分组的目的地址是多播 IPv 4 地址
（3）可靠传输，需要收到后返回确认分组
（4）路由器收到 LSU 分组后采用洪泛法转发，即向所有自己相邻的路由器转发（除了上级路由器，即从哪个路由器收到 LSU 分组）

OSPF 协议中链路状态数据库 LSDB 是什么？

（1）用来存储各种 LSA 的数据库
（2）洪泛一段时间之后整个网络的所有路由器的 LSDB 趋于一致，称为同步

OSPF 协议的最短路计算过程是什么？

（1）根据 LSDB 构建有向图
（2）通过这个有向图，利用最短路径算法，构建自己的路由表

OSPF 的报文封装是怎样的？OSPF 是哪个层次的协议？

（1）网络层协议
（2）利用 IP 协议来进行封装
（3）IP 首部的协议字段值是 89

OSPF 协议有哪五类信息分组？*

（1）Hello 分组，用于维护邻居关系（维护邻居关系表）
（2）DBD：向邻居路由器发送自己 LSDB 中所有链路状态的摘要
（3）LSR：向邻居路由器请求链路状态信息
（4）LSU 和 LSAck：用于洪泛自己的 LSA，使整个链路的 LSDB 趋于一致

OSPF 协议的具体工作过程是什么？（3 个阶段）

（1）开始：一开始用 HELLO 分组维护邻居关系
（2）同步：然后用 DBD 和 LSR 以及 LSU 和 LSAck 交换数据库信息
（3）后续更新：最后如果有更新的话，用 LSU 洪泛信息

路由选择协议 BGP

外部网关协议 - 边界网关协议 BGP 是什么？

（1）AS 之间的基于路径向量的路由选择协议
（2）不同 AS 内部度量路由的代价不一样，不可能找到最佳路由

eBGP 连接是什么？

（1）两个 BGP 边界路由器的通信连接，端口是 179
（2）eBGP 是 TCP 连接

iBGP 连接是什么？

（1）AS 内部任意两个路由器之间的连接
（2）同样是 TCP 连接，端口号 179
（3）AS 内部必须保证全联通，即任意两个路由器之间必须建立 iBGP 连接，哪怕没有物理连接

BGP 协议中通过 iBGP 和 eBGP 的路由告知情况是什么？

（1）利用 eBGP 协议从一端收到的路由可以通过 iBGP 告知 AS 内部的另一端
（2）利用 iBGP 从 AS 内部收到的路由，可以通过 eBGP 告知 AS 外部另一端
（3）AS 内部从 iBGP 对等端收到的路由不能通过 iBGP 告知 AS 内部另一个 iBGP 的对等端，为了防止环路
（4）BGP 路由采用增量更新机制，只有路由变化才更新，并且只更新变化部分

BGP 路由的一般格式是什么？


（1）（目的网络，经过 AS 路径，目的 IP 地址）
（2）经过 AS 路径中不允许出现相同的 AS
（3）内部的路由器通过 iBGP 收到来自对等端边界路由器发送的路由，从而知道别的网络的可达性，但是内部路由器到达边界路由器还是需要内部网关协议进行处理

BGP 如何避免路由环路？

（1）简单来说，就是 AS 收到一条路由更新发现自己的 AS 已经在 AS-PATH 中，则直接丢弃这个路由

（1）不同的边界路由器通过 iBGP 与 AS 内部路由器交换路由的时候发送本地偏好数值
（2）本地偏好由管理员设置
（3）偏好值更高的路由优先，上图中 R 1 的偏好值更高，所以 AS 1 中的各个路由器偏好从 R 1 离开 AS 1

AS 跳数规则是什么？

（1）选择 AS 跳数更少的路由，哪怕经过的路由器更多

热土豆算法是指什么？

（1）对于 AS 内部的一个路由器来说，如果到达另一个 AS 经过不同边界路由器的本地偏好相同，并且 AS 跳数也相同，则选择一个尽可能快的离开本 AS 的路由器
（2）不同的路由器利用内部网关协议 OSPF 或者 RIP，所以一般结果大家不一样

BGP 标识数值优先

（1）BGP 标识是边界路由器的标识，以 IPV 4 地址的形式，通常选择 BGP 路由器最大的 IPV 4 地址
（2）如果前 3 个选择算法都失效，则选一个 BGP 标识更小的 BGP 边界路由器离开 AS

（1）应用层协议，RIP 也是应用层协议
（2）传输层采用 TCP 封装，端口号 179
（3）网络层采用 IP 协议封装

三角路由问题是指，如果外地网络中的某个主机想要直接向移动主机发送一个 IP 数据报的时候还得先发送给归属网络中的归属代理路由器，然后再由归属代理路由器通过 IP 隧道转发给移动主机，这样就会造成信息发送低效的问题：

解决这个问题的一种方法是，固定主机也配一个通信代理，这个通信代理从移动主机的归属网络的归属代理那里获得移动主机的转交地址（即获得外地代理的地址），然后固定主机发送给移动主机的所有 IP 数据报，都通过通信代理发给外地网络的外地代理，由外地代理转交给移动主机，这样就不用每次都发送给移动主机的归属网络了

路由器是什么？其基本工作原理是什么？

路由器其实是一种具有多个输入输出端口的计算机，其任务就是分组转发，路由器的基本结构由路由选择部分和分组转发部分组成

路由选择部分的核心是路由选择处理机，其任务就是根据路由选择协议与其他路由器进行周期性的路由信息交换，以便构建和更新自己的路由表

分组转发部分由交换结构，一组输入端口和一组输出端口组成

信息从某个输入端口进入路由器，物理层将电信号转换成比特流之后向上交付给数据链路层，数据链路层从比特流中识别出帧，去掉帧头和帧尾向上交付给网络层处理；网络层处理数据分组，根据数据分组中的 IP 地址进行查表转发，如果没有匹配的条目，则丢弃分组；如果能够匹配，则按照匹配条目中的端口进行转发，并且网络层会修改数据分组中的一些值，比如将 TTL 减一，首部检验和等字段，然后交给数据链路层进行封装，数据链路层将数据分组封装成帧之后交给物理层，物理层将帧看作比特流，变换成电信号发送出去

如果数据链路层交付给网络层处理的是携带路由报文的路由分组，则将路由报文交付给路由选择处理机，路由选择处理机根据报文的内容更新自己的路由表，路由表一般是对网络拓扑结构变化进行计算最优化，而转发表是从路由表得到的，应该对查找过程最优化

输入缓存区用来处理新进入路由器但是还没有来得及处理的分组，输出缓冲区用来暂存已经处理完毕但是还来不及发送的分组，一般路由器的端口同时具有输入和输出的功能

软件定义网络的基本概念是什么？

在传统网络中路由器有两个基本功能，一个是为主机之间的通信转发分组，一个是进行路由选择，路由选择是用来决定往哪里转发分组路径最短的属于控制的功能，而转发分组则直接进行数据处理，属于数据的功能；因此路由器之间交互的信息也可以分为两类，一类是主机之间的分组，一类是交换的路由信息

路由器根据路由信息利用路由算法得到路由表，再根据路由表得到分组的转发表，这样就可以将路由器分为两个层面，一个是控制层面，主要用来控制分组从哪里走时间更短；一个是数据层面，用来之间转发分组和处理分组数据：

路由器的控制层面是通过与相邻的路由器交换路由信息，由软件计算得到的，这需要花费较多的时间

而 SDN 则是将这些路由器的控制层面全部剪除，所有的路由器不再互相交换路由信息了，而由一个远程的控制器统一调度所有的路由器

远程控制器可以掌握整个网络的状态，为每一个分组计算最佳的路由，为每个路由器生成正确的转发表，那么路由器只用查表转发就好了，所以 SDN 的核心思想就是将网络中的控制层面和数据层面分离，用远程的软件来控制网络中的各个设备

（1）传统路由器的功能包括控制层面 + 数据层面
（2）SDN 将路由器的控制层面剪除，通过远程控制器调度所有路由器

（1）SDN 的控制层面通过 OpenFlow 协议来访问和控制数据层面的物理设备

SND 中的广义转发是什么？

流表是 SDN 远程控制器来管理的，SDN 远程控制器利用 OpenFlow 协议通过安全信道来管理交换机中的流表

（3）SDN 通过流表来处理和转发数据包

SDN 的控制层包含哪两个部分？

（1）中间的 SDN 控制器（网络操作系统），掌控整个数据层面的信息
（2）最上层的网络控制应用程序，通过北向 API 从中间层获得网络信息，完成特定功能

（3）位于数据层面之外的分组交换机的网络控制功能

运输层的端口号是什么？

端口号其实不是一个实际的端口，而是运输层区分应用层进程的标识号，即应用层的应用进程标识 PID 会实际映射到运输层一个端口号，端口号其实更像是一种封装的概念，应用层的进程只用取监听运输层中某个端口号的信息，而不用分析运输层的所有信息从中找到发给自己的

为啥运输层不直接用 PID 来区分进程，而是用端口号来区分呢？

进程 PID 与操作系统深度绑定，应用进程重启或者发生什么变化进程 PID 都会发生变化，那此时正在网络中传递的数据报又知道该传给哪个进程呢？此时显然会影响网络上的通信，而一般服务器的一个固定的应用进程会持续监听一个固定的端口号，比如 HTTP 应用进程持续监听端口号 80，哪怕进程的 PID 发生变化，这个进程也是从 80 接收数据，不影响网络的数据封装和通信

这个思想也有点像面向对象的封装思想，将应用层进程和运输层分开，应用层出现变化的时候不影响运输层接收数据

TCP 的三次握手

TCP 三次握手（三报文握手）建立连接的过程是什么？

（1）客户端发送一个连接请求报文，SYN = 1，seq = x，不携带数据，但是消耗一个序号
（2）服务器返回一个对连接请求的确认报文，SYN = 1，ACK = 1，ack = x + 1，seq = y，y 随机指定，不携带数据但是消耗序号
（3）客户端发送一个普通确认报文，SYN = 0，ACK = 1，ack = y + 1，seq = x + 1，可以携带数据了

只要是 SYN = 1，那就只占用一个序号，但是不携带数据

三次握手的序号字段值情况是什么？

（1）连接请求报文，SYN = 1,
（2）连接请求报文的确认报文，SYN = 1, ACK = 1
（3）普通确认报文，SYN = 0, ACK = 1

三次握手的 seq, ack 情况是什么？

（1）seq = x, ack = 0
（2）ack = x + 1, seq = y
（3）seq = x + 1, ack = y + 1

这里的 x 和 y 都是随机指定，并且 x 和 y 没有关系

为什么三次握手中还需要最后一次握手？两次握手不行吗？

（1）不行，因为两次握手的话第一次客户端发送连接请求报文，服务器接收之后就开始等待接收数据
（2）如果在双方都已经传输完毕数据情况下，来了一个延迟很大的连接请求报文，服务器收到之后直接开始等待接收数据，但是没有谁给他发送，所以资源被浪费了

三握四挥中每个报文序号和携带数据总结

三次握手

（1）客户发给服务器，连接请求报文，第一次握手：不携带数据，但是会消耗一个序号
（2）服务器非给客户，连接请求确认报文，第二次握手：不携带数据，但是会消耗一个序号
（3）客户发给服务器，对连接请求确认报文的确认，第三次握手：可以携带数据也可以不携带数据，如果不携带数据则不消耗序号（哪怕带了一个序号，后续传数据的时候这个序号也会被重复使用，即不被消耗；但如果携带了一个数据则消耗序号，所以不管怎么样，第三次握手的序号就是 TCP 连接发送的第一个数据序号）

四次挥手

（1）第一次挥手，客户端发给服务器，它可以携带数据，但是一般不携带（408 不考虑携带数据），TCP 规定 FIN 报文即使不携带数据也要消耗一个序号

（2）第二次挥手，服务器发给客户端，普通的 ACK 确认报文，它可以携带数据；服务器接收后从客户端到服务器连接断开

（3）第三次挥手，服务器发送给客户端 FIN 报文，它可以携带数据，但是一般不携带（408 不考虑携带数据），TCP 规定 FIN 报文即使不携带数据也要消耗一个序号

（4）第四次挥手，客户端发给服务器对于 FIN 报文的普通 ACK 确认报文，这个理论上可以携带数据，但是之前从客户端到服务器的连接已经断开，所以实际上不会携带数据

这些可以携带数据的报文可以携带 HTTP 请求，以及 web 数据，即可以在请求释放，或者确认报文中携带 HTTP 中的数据

TCP 拥塞控制

TCP 拥塞控制的几个假设是什么？

（1）接收方可用空间无限大
（2）数据发送以 MSS 为单位，MSS 是每个 TCP 报文段的最大数据载荷
（3）cwnd 是拥塞窗口，swnd 是发送窗口，rwnd 是接收窗口

慢开始算法是什么？

（1）每个 RTT 中，发送方每收到一个确认报文，cwnd + 1
（2）因此按照 RTT 来说，cwnd 是指数增大

拥塞避免算法是什么？

（1）每经过一个 RTT，发送方的 cwnd + 1
（2）拥塞避免不改变慢开始门限之类的

超时重传会发生什么？

（1）慢开始门限变为原来的一半
（2）cwnd 变成 1
（3）重新执行慢开始

快重传算法是什么？

（1）接收方不是捎带确认，而是立即确认
（2）接收方收到了乱序误码，仍然发送对已接受的报文确认
（3）发送方连续收到 3 个重复确认报文，立即重传，而不是超时重传

快恢复算法是什么？（收到 3 个重复 ACK 之后，个别报文丢失的处理）

（1）慢开始和 cwnd 都变为原来的一半
（2）执行拥塞避免算法

根域名服务器告诉. com 顶级域名服务器的 IP 地址，于是本地域名服务器向顶级域名服务器发送 DNS 请求

顶级域名服务器接下来该项本地域名服务器返回一个权限域名服务器的 IP 地址了，本地域名服务器下一步需要向权限域名服务器发送 DNS 请求

一个权限域名服务器要对应一个区，这里区的划分有多种，一种划分方式是权限域名服务器将所有的 XXX. xyz. com 的 XXX 组合全部包含在了一个区中，这个权限域名服务器有所有 XXX. xyz. com 域名对应的 IP 地址，此时顶级域名服务器发送给本地域名服务器的权限域名服务器 IP 地址就是这样分区的权限域名服务器，然后本地域名服务器直接向这个权限域名服务器发送 DNS 查询，权限域名服务器就直接返回 abc. xyz. com 的 IP 地址了

本地域名服务器向顶级域名服务器发送 DNS 查询，顶级域名服务器返回大一点的 XXX. xyz. com 的权限域名服务器 IP

HTTP 的三种请求过程是什么？（1.0，非流水线，流水线）

在做题的时候默认是流水线请求方式，流水线请求忽略了连续发送请求的时候请求之间的延迟

这里的非持续连接不考虑四次挥手的过程，这里每次请求对象收到数据之后就立刻关闭连接

此外如果题目中说了 MSS 或者发送窗口，接收窗口这些信息，还得考虑拥塞控制的慢开始算法

（1）1.0 就是最原始的非持续性连接方式
（2）持续连接非流水线，就是针对每个资源一个个单独发送请求，获得响应，然后再发送下一个请求，再获得响应
（3）持续连接流水线，就是针对所有资源连续发送请求

HTTP 持续和非持续；流水线和非流水线区别是什么？

（1）建立 TCP 连接，在最后一次握手时发送请求
（2）非持续连接，每请求完一次资源，得到响应之后都会断开连接，请求下次资源需要重新建立 TCP 连接
（3）持续连接，请求完一次资源，TCP 连接不断开，后续不用重新建立 TCP 连接，直接发送请求，然后得到资源响应
（4）持续非流水线，请求完一次资源，TCP 连接不断开，后续请求资源都是单个单个进行，请求一次，获得资源响应，然后再请求一次，再获得响应（有点像 SW 协议），题目一般以资源单位个数为单位而不是 MSS
（5）持续流水线，请求完一次资源，TCP 连接不断开，后续请求资源可以连续发送多个资源的请求，然后获得响应，类似拥塞控制那种，题目一般以资源单位个数为单位而不是 MSS
（6）说了 MSS 切换成拥塞控制过程，这个时候别管什么流水非流水，直接按照拥塞控制过程分析即可

一般单纯的使用流水线或者非流水线题目都是以资源个数为单位的，这时默认非流水线方式；说了 MSS 直接切换成拥塞控制过程即可

路由器：分隔广播域，因为路由器工作在数据链路层和网路层和物理层，它不单单只根据 MAC 地址广播 IP 数据报，并且对于目的 IP 全 1 的报文它也不会进行广播转发，它有点像是小型计算机了

交换机：分割冲突域，这时因为交换机工作在数据链路层和物理层，并且交换机采用的是存储转发的机制，这样不同的数据帧到达交换机的时候是先存储再转发，不会出现冲突，交换机并不会分割广播域，交换机会将广播帧从自己的端口全部转发

集线器：无脑转发，它工作在物理层，主要作用是对信号进行整型放大等，这种数据到达集线器之后里面的信道都是共用的，集线器没有存储转发的功能，这就导致碰撞冲突的产生

各种设备总结

中继器：中继器工作物理层，没有存储转发的机制，所以中继器连接的两边的网段必须协议和速率一致
集线器：实际上是多个端口的中继器

中继器和集线器无法隔离冲突域，也无法隔离广播域

网桥：网桥也是用来连接扩展两个以太网的，但是网桥比集线器的功能更多，其工作在数据链路层（当然包含物理层的功能）
交换机：交换机实际是具有多个接口的网桥，称为以太网交换机，又称为二层交换机，这里的二层意思是交换机工作在数据链路层和物理层

交换机由于存储转发机制可以隔离冲突域，但是无法隔离广播域

路由器：可以看成一个小型的计算机，可以隔离广播域

CSMA /CA 和 CSMA/CD 的退避算法总结

CSMA/CA

在边监听边发送的时候如果出现了碰撞，则会执行退避算法，基本等待时间是 2τ，系数是 0,….2k−1，k 这里是重传次数，重传超过 10 次之后 k=10 保持不变，重传超过 16 次直接丢弃这个帧向上报告

CSMA/CD

如果第一次检测信道不是空闲的，那么就会转而执行退避算法

退避算法有一个计时器，如果信道忙，则是冻结计时器，等到信道空闲，再等待一个 DIFS 间隔则会启动计时器倒计时，当计时器倒计时到 0 的时候发送帧，这里的计时器倒计时时间就是退避的时间

基本退避时间单位是时隙长度（不是 DIFS 或者 SIFS），第 i 次超时重传，就从 (0, ........ 24+i−1) 中选择一个系数
