原码一位乘的硬件原理（其实计算机里面只有无符号乘）

硬件结构

原码进行操作时只是数值位参与运算，符号位进行异或操作

此时数值位就是绝对值参与运算了，所以可以直接用无符号的硬件来实现原码的数值位运算

最后的结果再加上符号位异或的结果即可

在进行无符号乘法的时候，计算机硬件主要包含下面几个结构：

MQ 是乘商寄存器，用于存放乘数以及乘积结果的低位

ACC 是累加寄存器，用于存放中间结果，以及乘积结果的高位，中间结果会作为一个操作数送入 ALU

x 是 ALU 的另一个操作数，存放的是被乘数

Cout 是加法器执行加法之后的进位信号

ALU 算数逻辑单元，这里用于加法

控制逻辑计数器 Cn 用于控制加法，右移的次数以及右移操作，Cn 的大小取决于乘数 y 的数值位位数

溢出判断

手算判断

对于 n 位的无符号数乘 n 位的无符号数，如果最后结果用 2 n 位保存，一定不会溢出（1111 乘 1111 结果是 225，但是 8 位保存结果的话最大可以保存 255）

如果最后结果用 n 位保存，则直接进行十进制验算即可，比如 1111 乘 1111 结果是 225，显然范围超出了 4 位二进制无符号数的范围（0 ~ 15）

机器判断

像这样 n 位乘 n 位，最后结果用 2 n 位保存，那肯定不会溢出

但是如果这里用 2 n 位保存中间结果，最后截取后面 n 位作为结果的话，如果前面前 n 位不全为 0，那就是有溢出（很显然，因为是无符号数，不存在符号位，n 位结果超了那数值就是超了）

溢出判断

手算判断

如果是 n 位乘 n 位，用 2 n 位保存就不会发生溢出

如果是 n 位乘 n 位，用 2 n 位保存中间结果，截取后 n 位作为最后的结果，由于是补码运算，我们直接手算两个补码的真值相乘的结果真值，看这个真值是否可以用 n 位的补码表示，n 位补码的范围是 [−2n−1,2n−1−1]，如果乘积真值超过了这个范围，则会溢出

机器判断

如果是 n 位乘 n 位，用 2 n 位保存就不会发生溢出

如果是 n 位乘 n 位，用 2 n 位保存中间结果，截取后 n 位作为最后的结果，那么只有当前 n + 1 位全是 1 或者 0 的时候才没有发生溢出

这是因为取后n bit作为补码乘法的结果的时候，这n位的范围是 [−2n−1,2n−1−1]

因此对于从前往后的第n + 1位，它是截断的后n位的符号位，如果前n + 1位不是全0或者全1，那就超过了这n位的范围是 [−2n−1,2n−1−1]，所以溢出

（2）这一轮确定是+y 还是-y，可以直接根据这一轮的商来确定，如果商 1，则-y，如果商 0 则+y

这两个规律就可以用来控制电路了

ALU 操作之后就看看进位，如果进位为 1，那么这一轮就商 1；如果进位为 0，那么这一轮就商 0；然后左移一位，然后再确定输入的操作数，如果这一轮的商是 0，那么操作数就加 y，如果这一轮商是 1，那么操作数就加-y

真题

2020 年

（1）

因为计算机中的乘法实现就是通过不断的加法以及移位进行的

（2）

控制进行ALU计算和移位的次数

（3）

没有乘法指令的时候执行最长，因为此时乘法是很多个加法指令和移位指令组合实现的乘法效果，这些指令会比单独的乘法指令多花费很多取指访存的额外时间

阵列乘法的时间最短，因为他的一些操作是并行的

（4）

由于对于硬件来说是2n位保存结果，2n位进行计算，一定不会溢出，所以这里可以直接笔算出结果，然后转成二进制再用16进制表示

结果真值是 232−2

其实就是 232−1−1

所以二进制就是：0000 0000 0000 0000 0000 0000 0000 0000 1111 1111 1111 1111 1111 1111 1111 1110

换成16进制就是00000000 FFFFFFFE H

根据这里的二进制位，对于带符号乘法来说，如果取后n位作为结果，按照硬件乘法的结论，只有前n + 1位，这里是前33位都为0或者都为1的时候才不会溢出，显然这里前33位的最后一位是1，所以会发生溢出

而对于无符号乘法运算时，只要前n位，这里时前32bit，没有1，那结果就是没有溢出

所以umul () 没有溢出，imul () 结果溢出

（实际上将 231−1 左移一位即可，然后观察有没有溢出，别想着真正的乘法硬件实现）
