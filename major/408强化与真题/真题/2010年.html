文件目录

文件控制块是什么？包含哪些信息？

文件的物理位置是文件在外存中的位置，而不是内存中的位置

文件控制块与文件目录的关系是什么？

多个文件控制块放在一起组成文件目录，文件控制块其实就可以看作是目录中的一个目录项

文件元数据是什么？

一个文件包含两部分内容，分别是文件的信息和文件的元数据（属性信息）。文件元数据包含用来描述一个文件的特征的系统数据，诸如访问权限、文件拥有者、文件大小以及文件数据块的分布信息。

索引结点 inode 与索引结点编号是什么？

索引结点是外存中存放文件元数据的一块区域，我们一旦找到了索引结点，我们也就找到了这个文件的元数据，索引结点与文件是一一对应的。

索引结点有自己的索引结点编号，只要知道索引结点编号，那么就可以通过查 inode 表找到这个 inode 在磁盘中的地址，从而获取这个 inode 索引结点了

FCB 与索引结点的关系是什么？

FCB 也就是文件控制块，它其实也是目录文件中的一个目录项，inode 索引结点主要是将目录项中除了文件名之外的信息全部摘出来了，单独存放再外层中，保留了一个 inode 编号来找到 inode 结点

而 FCB 则是直接将 inode 中的文件元数据一股脑放在目录项中，与文件名形成一个大的目录项

可想而知，采用 FCB 的目录文件将会变得非常大

引入索引结点之后的目录和目录项是什么?

目录是一种特殊的文件，它包含了一组目录项，目录也是保存在磁盘中的，目录文件也是目录

目录中的一个目录项，表述了这个目录下的某个文件的信息，包括这个文件名以及这个文件对应的索引结点编号

只要通过文件名找到了目录项中的索引结点编号，然后通过查索引表知道了索引结点位置，然后从索引结点中拿到文件的元数据，获取到了元数据，然后就可以访问文件了，一个目录项对应一个文件实体，这个目录项存储在上级目录文件中

注意目录本身也是文件，它仍然在上级目录中对应有目录项，如果要访问这个目录文件，仍然需要在它的上级目录的目录项中找到这个目录的索引结点编号，然后访问索引结点，然后拿到这个目录文件的元数据，然后才能访问这个目录文件

索引结点的结构是什么？包含哪些信息？

文件类型：用来说明这个文件是一个实际的文件还是一个目录文件，还是一个软链接等等

存储权限：跟这个文件的访问权限有关

物理地址：通过这个物理地址来获取文件逻辑地址向物理地址的转换

链接计数：跟硬链接有关，增加一个硬链接，链接计数+1，连接计数也就是引用计数

RIP 要求自洽系统 AS 中的每一个路由器，都要维护自己到 AS 内其他每一个网络的距离，这些距离构成了一个距离向量

RIP 协议的封装是什么？RIP 是哪一层的协议？使用什么协议封装？发送形式是什么？

RIP 协议是应用层的协议，他使用的是 UDP 协议格式来给自己封装，RIP 协议就处在 UDP 协议的数据部分，然后接着往下在网络层使用 IP 协议来继续封装

RIP 的工作特点是什么？和谁交换信息？交换什么信息？多久交换一次？

（1）只和相邻的路由器交换信息
（2）交换的信息是自己的路由表，即本路由器到 AS 系统中各网络的最短 RIP 距离，以及到达各网络应该经过的下一条路由器
（3）大概经过 30 s 的时间就周期性交换信息，当然，如果网络拓扑发生了变化也需要交换信息，即触发更新

（1）相同下一跳到达目的网络，RIP 距离改变
（2）发现新的网络可达信息

RIP 的坏消息传得慢是什么？

缺点是坏消息传播慢（路由环路，RIP 距离无穷计数），即 RIP 容易被相邻的路由器传播的信息所误导导致进入一个死循环，比如路由器 R 1 本身到网络 N 1 的距离变成不可达，R 1 会设置为 16，但是路由器 R 2 中有一条可以通过 R 1 到达 N 1 的记录，路由器 R 2 会先发给 R 1 这个可以通过 R 2 到达 N 1 的路由表，当路由器 R 2 向路由器 R 1 发送这条记录的时候 R 1 会根据这条坏消息更新自己的路由条目，然后 R 1 又把这个信息给 R 2，R 2 继续更新到达 N 1 的条目，就这样循环下去，一直到两个路由器到达 N 1 的距离都变成了 16，此时两个路由器才知道 N 1 不可达了：

traceroute 的原理是什么？

跟踪路由的基本原理是源主机首先发送一个 TTL = 1 的 ICMP 回送请求报文，这个报文到达第一个路由器 TTL 减一，此时这个路由器就会发送给源主机一个 ICMP 差错报告，类型是时间超时，这样源主机就知道了第一跳的路由器的 IP 地址

接着源主机再发送一个 TTL = 2 的 ICMP 回送请求报文，同理，得到了到达目的主机的第二个路由器的 IP 地址：

最后源主机发送一个 TTL = 3 的 ICMP 回送请求报文，这个时候目的主机 H 2 可以收到这个 ICMP 报文，所以会发送一个回送回答的 ICMP 数据报，这样 H 1 就会知道已经跟踪到了最后一个站点

traceroute 命令中沿途路由器和目的主机发送的各是什么报文？

源主机发送的是 ICMP 回送请求报文，不过其中的 TTL 会递增

沿途路由器收到 ICMP 回送请求报文之后，由于 TTL 会减 1，所以不会转发，而是发送给源主机 ICMP 差错报告报文，通过此来发现沿途的路由器

源主机收到 ICMP 差错报告报文之后会不断递增TTL 重新发送 ICMP 回送请求报文，一直到目的主机收到这个报文，此时目的主机发送 ICMP 回送回答报文给源主机

其实这个题考察的是分区的概念，比如你这里的查 abc. xyz. com

本地域名服务器向根域名服务器发送 DNS 请求

根域名服务器告诉. com 顶级域名服务器的 IP 地址，于是本地域名服务器向顶级域名服务器发送 DNS 请求

顶级域名服务器接下来该项本地域名服务器返回一个权限域名服务器的 IP 地址了，本地域名服务器下一步需要向权限域名服务器发送 DNS 请求

一个权限域名服务器要对应一个区，这里区的划分有多种，一种划分方式是权限域名服务器将所有的 XXX. xyz. com 的 XXX 组合全部包含在了一个区中，这个权限域名服务器有所有 XXX. xyz. com 域名对应的 IP 地址，此时顶级域名服务器发送给本地域名服务器的权限域名服务器 IP 地址就是这样分区的权限域名服务器，然后本地域名服务器直接向这个权限域名服务器发送 DNS 查询，权限域名服务器就直接返回 abc. xyz. com 的 IP地址了

另一种分区方式是一个权限域名服务器包含了 XXX. xyz. com 中除了 abc. xyz. com 的可能，然后 abc. xyz. com 分在另一个区，即对应另一个权限域名服务器中

此时顶级域名返回的是 XXX. xyz. com 的权限域名服务器（这个包含的可能最多，是一个更大的权限域名服务器），然后这个权限域名服务器再返回给本地域名服务器 abc. xyz. com 对应的权限域名服务器，然后本地域名服务器再去向这个小点的分区的权限域名服务器发送 DNS 查询，然后这个小点的权限域名服务器就返回给本地域名服务器 abc. xyz. com 的 IP 地址了

那么对于 www.abc.xyz.com 的DNS查询过程就是：

本地域名服务器向根域名服务器发送 DNS 查询，根域名服务器返回顶级域名服务器 .com的 IP

本地域名服务器向顶级域名服务器发送 DNS 查询，顶级域名服务器返回大一点的 XXX. xyz. com 的权限域名服务器 IP

本地域名服务器向大一点的 XXX. xyz. com 权限域名服务器发送 DNS 查询，这个权限域名服务器返回 abc. xyz. com 权限域名服务器的 IP（小一点的分区）

本地域名服务器向 abc. xyz. com 权限域名服务器发送 DNS 查询，这个权限域名服务器进一步分区的话它对应的是 XXX. abc. xyz. com 的大一点的权限域名服务器，它返回的就是 www.abc.xyz.com 的服务器 IP 地址，这个 IP 地址就是用户想要访问的 IP 地址，返回给本地域名服务器的时候查询就结束了

所以一共最多就是本地域名服务器发出 4 次 DNS 查询

也可以这样理解

本地->根，根域名服务器知道所有. XXX 的顶级域名服务器，它告诉本地域名服务器去找. com 的顶级域名服务器

本地 ->.com顶级域名服务器，. com 顶级域名服务器知道所有 XXX. com 权限域名服务器地址，它告诉本地去找 xyz. com 权限域名服务器

本地-> xyz. com 权限域名服务器，这个权限域名服务器知道所有 XXX. xyz. com 权限域名服务器地址，它告诉本地与找 abc. xyz. com 权限域名服务器

本地-> abc. xyz. com 权限域名服务器，这个权限域名服务器知道所有 XXX. abc. xyz. com 服务器地址，它告诉本地 www.abc.xyz.com 服务器地址，这个地址即为用户所求

所以一共最多 4 次 DNS 查询，上面分区理解方式反而更麻烦了

如果权限域名服务器要求更少的话可以划分一个区，权限服务器就只有一个 xyz. com，这个权限域名服务器可以直接返回 www.abc.xyz.com
