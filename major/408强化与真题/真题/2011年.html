循环队列各种类型判空的方法是什么？

判空或者判满主要是假设原始队列为空，然后加入一个元素，分析 rear 和 front 指向从而得到初始为空的情况

rear 指向最后一个元素

加入一个元素的代码就是:

rear = (rear + 1) % M
q[rear] = value

假设一开始为空，那加入一个元素之后要保证 front 和 rear 都指向这个元素，所以 rear 必然在 front 前面一个

所以判空语句就是 (rear + 1) % M == front，结果为 true 的时候为空

队列判满，队列满的时候还是保证 rear 指向最后一个元素，front 指向第一个元素，这个时候整个数组不能够全部放入元素，因为这个时候仍然满足 (rear + 1) % M == front 与队列空冲突，所以长度为 N 的数组只能放入 N - 1 个元素

所以判满语句就是 (rear + 2) % M == front，结果为 true 的时候为满

M 是数组的长度即 N

rear 指向最后一个元素的下一个元素

加入一个元素的代码是：

q[rear] = value
rear = (rear + 1) % M

假设一开始为空，加入一个元素之后要保证 fornt 指向第一个元素，rear 指向第一个元素的下一个元素，所以空的时候 front 和 rear 必然指向同一个位置

所以判空语句就是 rear == front，结果为 true 的时候为空

当队列满的时候，假设数组的长度为 N，由于 rear 要指向队尾元素的下一个，所以数组中应该只能放入 N- 1 个元素，如果放入 N 个元素，那此时 rear 和 fornt 指向同一个位置，与判空矛盾了

所以判满语句就是 (rear + 1) % M == front，结果为 true 的时候为满

上述 M 就是数组长度 N

总结：

判断队空：就是在假设队空的情况下加入一个元素保证指针指向来分析队空的时候的指向，从而判断队空的条件

判断队满：就是在假设队满的情况下，利用此时的指针指向来分析判断队满的条件

取模一定是数组的长度而不是队列的元素长度

森林转为二叉树的一些结点对应关系

森林中分支结点与转换之后二叉树的右指针域为空的结点之间关系

转换后的二叉树的右指针域为空的结点为森林中没有右兄弟的结点个数，这些结点分为两类一类当了儿子没有右兄弟，一类没有当儿子没有右兄弟

对于森林中的分支结点，每一个分支结点必然有儿子，所以每一个分支结点都会贡献一个没有右兄弟的儿子，所以分支结点个数就等于当了儿子的没有右兄弟的结点个数

然后森林中最后一个根结点也没有右兄弟，这个结点是没有当儿子没有右兄弟

所以分支结点个数 + 1 就是总的没有右兄弟的结点个数

森林转换成二叉树的结点中左指针为空的结点特征

进程上下文，保存断点，保存现场，这些有什么区别？

进程上下文通常用进程PCB来表示，包括寄存器的值，进程状态，以及内存管理信息等等

程序断点：保存程序断点，这个是中断响应中的操作，包括PC的值和状态寄存器PSW，由硬件实现，这是因为软件一般无法直接访问PC和PSW的值

保存现场：程序现场是指从程序开始到中断位置处程序所使用的用户可见的一些寄存器的值，这些值软件指令可以访问，所以放在中断服务程序的开头进行保存

抖动与各种分配算法处理措施

抖动是指频繁的进行页面的换入换出

抖动的根本原因是给进程分配的页框太少了，任何页面置换算法都会出现抖动现象

但是，一个合适的调度算法是可以减轻抖动现象的，比如 FIFO 算法就没有考虑到
局部性问题，那么它的抖动就会更有可能出现；但是如果采用的是 LRU 算法则可以消除一些抖动，但是，如果分配给进程的页框还是很小的话抖动仍然可能发生

因为程序访问的页面序列的规律是不变的（局部性原理），你更符合局部性原理的算法当然换入换出就少一些

所以为了减少抖动，本质是增加进程可以分配得到的物理块，能让进程分配的物理块变多的措施都可以减少抖动，比如增大内存，比如撤销部分内存

磁盘对换区是什么？

为了加快磁盘IO的速度，通常将页面换出的时候先暂时存放在磁盘的对换区中，如果这个页面后续还需要使用的时候可以直接从对换区中再读取放入内存

对换区在物理上是连续分配的，这样取数据的时候可以减少磁头移动，因此比读磁盘的其他地方所花费的IO时间更少一些，所以它主要是为了减少IO时间的，而不是减少抖动
