数据通路与流水线

6,904 字约 16 分钟2026-07-29

基本概念

组合逻辑元件

（1）输出不受时钟控制
（2）输入进入部件，经过一定延迟得到输出
（3）输出一直保持，直到输入改变

四种常见的组合逻辑元件

状态存储元件

（1）输入受到时钟控制
（2）被写入保持输出值和写入值相同（读寄存器和 Cache 看成组合逻辑，写的时候看成状态元件，写的时候保持输出值和写入值相同，在写 RTL 语言中，同样看成状态元件）

最典型的就是寄存器

时钟周期的定义

从一个状态元件到另一个状态元件，中间经过组合逻辑元件，这个过程称为一个时钟周期，这也是在多周期周期写 RTL 语言的依据

单周期数据通路

一些基本概念

（1）单周期数据通路控制信号是一次同时生成，并且指令执行过程中一直保持
（2）单周期数据通路中每个部件只能被使用一次
（3）单周期数据通路的 CPI = 1

单周期 R 型指令的执行过程

指令流水线

指令流水段由哪几个部分组成？

流水线中的机器周期，时钟周期，指令周期的关系是什么？

（1）流水线中一般一个阶段花费一个时钟周期，即机器周期= 时钟周期（知道这个即可）
（2）流水线中稳定情况下一个时钟周期有一条指令执行完毕，所以逻辑上指令周期= 时钟周期
（3）指令字长=存储字长情况下，存取周期 = 时钟周期

机器周期就是取指令一次的时间，流水线中默认指令字长= 存储字长，所以机器周期就是取指阶段的时间

在流水线中，一般就考试最常考的就是 5 端式流水线，一个指令被划分为 5 个阶段，每个阶段规定花费一个时钟周期（这里是自己规定的）

而机器周期规定是完成一个阶段操作的时间，这里设定为最长的取指操作时间，在这里 5 端流水线中，那么就有机器周期 = 时钟周期了

并且在指令字长 = 存储字长的情况下，一次读取主存的操作就可以把指令取出来，所以就有机器周期 = 时钟周期 = 存取周期

在流水线中，一条指令如果单独去看的话是需要花 5 个时钟周期才能执行完毕，但是在稳定以及理想状态下，每过一个时钟周期就有一条指令执行完毕，所以在逻辑上就是指令周期 = 时钟周期

因此在稳定理想的情况下就有：

机器周期 = 时钟周期 = 指令周期 = 取指周期

流水线冒险总结

结构冒险

结构冒险是指硬件资源的冲突，也就是不同的指令在执行过程中用到了同一个硬件资源；比如 A 指令取数的时候要用到 Cache，但是 B 指令又处于取指令阶段，也要用到 Cache，这样就会出现冲突

解决方法：

（1）规定一个部件一个指令在执行的过程中只能使用一次，这样不同的指令在不同的阶段使用的部件就会错开，比如规定只能在指令取指阶段使用一次部件 A，那么某条指令处于取指阶段的时候其他指令都是别的阶段，所以就不会出现部件冲突

（2）增加一些部件，进行冗余，比如数据 Cache 和指令 Cache

数据冒险

数据冒险也就是后一条指令用到的数据来自前一条指令的结果，比如下图的例子：

第一条指令的结果 $1 寄存器会被后续四条不同的指令使用，但是只有第 5 条指令才能取到 $1 的值

解决方法：

（1）插入空操作，只要在第二条指令之前多执行几条空操作指令就好了，将后面的所有指令执行延后，这样就可以取到 $1 寄存器内容了

（2）插入气泡，即硬件阻塞，将指令的阶段往后延迟，其实和第一个空操作差不多

上图中第二条指令需要取第一条指令的执行结果 R 1，那么往后延迟就完事了，注意这里 IF 阶段不能延迟，这里只有将 IF 取到了之后才能发现是否阻塞

（3）采用转发技术，也就是旁路，它的意思是，根据上图，第二条指令需要用到的 R 1 的结果，其实在第一条指令的 EX 阶段已经得出了，只是没有写回寄存器，这个时候可以在 EX 阶段的运算器啥的部件引出一条硬件线路，那么第二条指令的执行阶段就可以直接通过这个硬件旁路来获得数据，不同非得等到第一条指令执行完毕才能得到 R 1 的数据：

控制冒险

控制冒险的原理如下所示：

上图中的 beq 指令，在 Ex 阶段执行操作得到结果，然后在 Mem 阶段根据结果决定是否跳转，并在 Mem 阶段结束的时候将跳转的值送到 PC，比如这里要跳转到 1000 存储单元处

那么在 ID, Ex, Mem 阶段与 beq 指令相邻的指令仍然在执行比如上图中的 16, 20, 24 单元位置处的指令，如果就这样直接跳转，那么这些指令执行了一半当然就会出现问题（因为按照程序逻辑你应该执行 1000 处的指令得到结果，但是这里反而多执行了邻近的三条指令，那这样这些指令也会得到一些结果，或者改变一些寄存器的值，就会与原来的程序逻辑冲突，这个就是控制冒险），所以正确的执行顺序是执行完 beq 的 Mem 阶段之后 PC 取指开始执行 1000 单元处的 lw 指令

解决方法

（1）通过加入空指令或者阻塞，将 16, 20, 24 单元处的指令一直往后延，延到 Mem 阶段结束再开始执行 16 存储单元的指令，这个时候就知道是应该顺序执行还是跳转了，如果是跳转，那么 IF 取指取得就不是 16 存储单元处得 ori 指令，而是 1000 处的 lw 指令，这里阻塞是阻塞分支指令之后的指令，他们被阻塞的包括 IF 阶段

（2）进行预测；分为两种静态分支预测和动态分支预测；

静态分支预测就是跟历史无关，一律认为所有的分支指令转或者不转，比如假设 CPU 认为所有的分支指令都不转，那么分支指令在执行的时候相邻的指令仍然会执行，但是如果分支指令的结果是转，那么根据下图，就有三条指令执行错误，所以必须得将这三条指令的控制信号清零，相当于将这三条指令延后了 3 个时钟周期，浪费了 3 个时间片（流水线阻塞损失的时钟个数称为时间片）；当然，如果预测对了，那就一个时钟周期也没浪费

动态分支预测就是根据局部性的原理，根据前面的分支的结果来动态预测当前分支会不会跳，这种预测的准确度要高于静态分支预测

load - use 冒险是什么？

（1）第二条指令要用的数据由上一条 load 指令从主存取出来而产生的冒险
（2）上一条 load 指令要等到 MEM 阶段才会得到结果，因此 load-use 冒险无法只单单用旁路解决

load - use 冒险是一类特殊的数据冒险，它跟普通的数据冒险不一样，load -use 冒险是第二条指令要用的数据由上一条 load 指令从主存取出来而产生的冒险，如下所示：

上述 beq 指令的 EX 阶段必须得用到上一条 load 指令的结果进行作差，这里与普通数据冒险的区别在于，普通的数据冒险上一条指令产生结果是在 EX 阶段之后就产生了，仍然在下一条指令必须用到数据的 EX 阶段前面，所以可以用一个数据旁路引到下一条指令的 EX 阶段

但是 load - use 指令实际数据产生是在访存之后即 Mem 阶段，这个阶段与下一条指令的 EX 阶段是同时发生，所以这里下一条指令进行 EX 阶段要用到的数据上一条指令还没实际产生呢，当然就不可能通过旁路引过去

解决方法

（1）简单来说，就是阻塞和旁路结合，这样只用阻塞一个时钟周期即可

load-use 指令可以完全采用阻塞来进行处理，即将 beq 指令往后延迟，但是这种方法不好

所以 load - use 指令采用的方法是阻塞与旁路结合的方式，即 beq 在 ID 阶段检测到 load - use 冒险之后主动进行阻塞

流水线阻塞的具体操作是什么？

以上面的 load-use 冒险为例，指令 i 3 在 ID 阶段检测到了 Load-use 冒险，此时需要进行一次阻塞

此时 i 3 和 i 4 一个正在译码，一个正在取指，它们此时都处在各自阶段的组合逻辑部分，它们此时都想将组合逻辑得到的结果写入到寄存器中，i 4 是想将 PC 取指的结果 i 4 写入寄存器，并在下一个时钟周期输入 ID 进行译码；i 3 是想将译码得到的控制信号写入寄存器，并在下一个始终周期写入 EX 进行控制执行

时钟周期 3 结束的时候寄存器状态是：

这里在第 4 个时钟周期结束时我们进行如下操作：

（1）将 i 3 译码之后的控制信号结果清零，不让其写入寄存器，也就是 ID/EX 寄存器清零

这个操作对于 i 3 来说相当于白干了，i 3 的控制信号不会进入第 5 个时钟周期，因此第 5 个时钟周期 i 3 不会进入 EX 阶段，即第 5 个时钟周期相当于 EX 阶段的组件空闲

这一步保证第 5 个时钟周期 i 3 不会进入 EX 阶段

（2）保持 IF 段的寄存器的值不变，仍然是第 3 个时钟周期结束的时候取出的 i 3 的指令

第 4 个时钟周期本来 IF 想要执行的操作就是取出 i 4，然后覆盖掉寄存器中的 i 3，这里我们不让其覆盖，仍然保持寄存器中是 i 3 的值；那么在第 5 个时钟周期的时候仍然是指令 i 3 进入 ID 译码阶段，即第 5 个时钟周期译码组件仍然进行 i 3 的译码

高级流水线技术

超标量处理器 (多发射技术)

超标量处理器意思就是每次取指，译码，执行，访存，写回的指令条数不止一条，其流水图像如下所示，简单理解的话就是有多套流水线处理部件：

超标量处理器的动态调度技术（动态多发射技术）

就是，根据上图，超标量是将 3 条指令叠在一起执行的，即取指，译码，执行，访存，写回都是每次操作三条指令；但是这三条指令可能会出现数据冒险啥的；动态调度技术就是解决这样的问题，其通过调度将 3 条没啥关联的指令放在一起共同执行，这样来避免冒险

超长指令字技术

这个技术是指假如有 A，B，C，D 等多条指令，编译器可以发现 ABCD 他们在执行阶段其实是可以并行操作的，那么就将 ABCD 的操作码放在一起，组成成一个长度超长的的新的指令，这样，这个指令在译码的时候译的是 ABCD 多条指令的操作码，那么执行的时候也是同时执行 ABCD 多条指令的操作

由于指令长度被加长了，那么显然存放它的 Cache 容量就得变大才行，此外，由于操作码全都放在了一起，所以译码电路也得升级才行，所以这个技术是对硬件有要求的

超流水线技术

这个技术其实是将流水段进一步划分，比如将取指 IF 流水段进一步划分为多个段，增加多组流水段寄存器，那么你后续的指令就不用等到上个指令的 IF 段结束再进入了，可以直接在 IF 段中间就直接取指：

这样当一条指令执行完毕之后，后续稳定状态下小于一个时钟周期就可以完成一条指令的执行；

这种技术其实是等价于一条指令的指令周期不变的情况下，划分更多的流水段，然后保证每个流水段是是一个时钟周期，其实等价于时钟周期变小了机器主频变高了

但是这种技术不能无线划分流水段，因为你流水段寄存器越多，中间过程的缓存延迟时间就更多，反而影响效率
