进程的虚拟地址空间是什么？

虚拟地址空间是 OS 为每个进程分配的虚拟内存视图，他是进程看到的内存世界，每个进程都认为自己独占整个内存，但是实际上 OS 通过 MMU 将虚拟地址空间与实际物理地址映射对应起来

每个进程所看到（假想的）地址空间都是一样的，如下所示，都是这样的模板：

当程序调入内存运行的时候就构成了进程的内存映像，也就是虚拟地址空间，这里虚拟地址空间的东西，其实就是进程存放在实际内存的东西，只不过进程以为自己独占了整个内存，但是实际上不是，实际上是 OS 帮内存做了一个映射，将内存存放在自己以为存放在整个内存的东西映射到了实际的物理地址

进程用自己假想的虚拟地址空间中的地址去访问数据，这个地址就是虚拟地址，OS 的 MMU 对这个地址做变换来映射到真实的物理地址，然后让进程访问到各种数据

进程的内存映像中有什么东西？


内核区

进程不可见，进程的 PCB 等数据结构放在此处，在进程看来它可以通过系统调用访问这个区域，事实上最后还是由 OS 做了转换来访问这个区域，进程只知道可以通过系统调用，利用这个部分的逻辑地址访问这个区域，但是这里面具体是什么进程无法得知

用户栈

函数调用的时候用户使用的栈空间，从高地址向低地址增长，同时存放函数中的局部变量

共享库的存储映射区

物理内存中只有一份的共享的库（比如动态连接库 DLL），这一部分由所有进程共享，这个区域就实现了进程访问这块共享的代码，就好像这些代码和数据是进程自己拥有的一样

堆

通过 malloc 分配的空间就在此处，向高地址增长

比如 char* ptr = (char*) malloc(100)，这里代码的含义就是在堆中申请一个空间，表示这个空间存放字符，同时返回这个空间的地址，放到 ptr 中，此时 ptr 指针指向的空间位置（指针中存放的地址所指向的位置），就位于堆中，这个位置存放的就是一个字符

至于这个指针本身所处的位置，则需要看这个指针在那里声明的，如果在函数中，则这个指针空间位于栈，如果在函数外面，则这个指针是全局变量，位于数据区

数据段

存放全局变量和静态变量的地方

代码段

程序的二进制，只读，可以被多个进程共享

代码段可以共享，虽然每个进程所访问代码段的时候使用的地址可能不一样，但是对于共享的代码段来说 OS 会将这些虚拟地址映射到同一个物理地址处

父子进程是什么？两者有什么关系？

进程通信-管道

匿名管道通信和命名管道通信是什么？

匿名管道通信：用于父子进程之间通信

命名管道通信：用户任意进程之间的通信

管道是如何实现的？基本读写单位？

（1）操作系统会在内核区开辟一个区域，这个就是管道，具体来说，是一个环形队列，进程通过 pipe 系统调用来进行读写管道
（2）进程利用一系列系统调用来完成读写，读写基本单位是字符

父子进程对管道的读写权限是什么关系？

（1）子进程会继承父进程对于管道的读写权限
（2）父进程撤销 OS 不会撤销管道，只有管道两端的读者和写者都是 0 OS 才会撤销管道释放内存

对管道读写的互斥情况是什么？（3 条）

（1）进程对管道的读写必须互相互斥进行，队列满的时候写进程阻塞，队列空的时候读进程阻塞
（2）同一时间段，只能由一个进程写，一个进程读，只有当进程 A 写完自己的所有数据，并且进程 B 读完 A 的所有写入的数据，才能允许进程 C 往管道写数据，是半双工通信
（3）管道中的每个字符只能被读一次，然后就失效，可以被写入覆盖

进程通信-信号（25 年大纲新增）

进程信号通信是什么？信号分为哪两类？

由一个进程或者操作系统发送信号给另一个进程进行通信

信号分为：
（1）操作系统（缺省）信号
（2）用户自定义信号

当进程在 CPU 运行的时候信号到来，会被保存到哪里？

（1）保存在进程的 PCB 中
（2）PCB 中维护两个字段，一个 receive 字段用于保存信号编号，一个 sigmask 字段用于表明这个信号需不需要优先处理
（3）每个信号本质是一个整数

信号有哪三种处理手段？

（1）忽略信号，但是不能忽略 sigkill 和 sigstop 这两个信号
（2）执行信号默认操作，比如 OS 会事先定义好一些进程关于信号的处理函数，进程执行这些函数即可
（3）捕获并处理信号，用户可以不让进程执行 OS 定义好的默认处理函数，而是捕获信号，执行用户自定义的处理函数，sigkill 和 sigstop 这两个信号不能被捕获

信号有哪些方式产生？

（1）根据键盘产生，比如按下 Ctrl + C 产生 sigint 信号
（2）程序异常时，OS 会向进程发送信号终止进程
（3）利用系统调用函数，比如 kill 系统调用，一个进程通过 kill （）系统调用向另一个进程发送信号

（4）利用软件产生信号，比如 alarm（）函数，当它的倒计时结束的时候就会向进程发送一个信号
（5）硬件异常产生信号，当出现硬件异常，它被 OS 检测并通知内核，内核向当前进程发送信号

信号在什么时候会被处理？

一般信号并不都是及时响应的，对于不及时响应的信号：

（1）对于 OS 的信号，需要在内核态进行处理，为了避免 CPU 变态，通常在一个进程进行外部中断，或者异常的返回的时候顺便在内核态进行处理

（2）对于用户编写的信号，在用户态进行处理，通常在一个进程进行外部中断，或者异常的返回的时候先切换到用户态，PC 转到用户自定义的函数进行处理，处理完了再返回内核态恢复现场，然后再返回

线程

线程是什么？

（1）可以简单将线程看作进程中执行部分代码模块功能的一个动态执行过程

这里没有画出地址空间的内核区

进程与线程的区别是什么？

（1）进程是 OS 中资源分配的基本单位
（2）线程是 OS 中调度的基本单位

OS 中的进程，即正在进行的程序，他可以看作是代码动态执行的整个过程，包含了静态的代码和各种资源的变化，它是 OS 分配资源的基本单位，是一个具有实际功能的程序在一个数据集合上的一次动态执行过程，同时也是 OS 资源分配的调度的独立单位

进程中的线程，线程是进程中的一个子执行任务，负责进程中的实际程序执行，一个进程至少含有一个线程，当然一般进程含有多个线程，可以简单认为线程是进程程序中部分功能代码模块的执行动态过程，线程也可以简略的认为是轻量级进程，线程是 OS 调度的基本单位

线程继承进程什么东西（线程共享进程什么东西）？

线程独有的东西有哪些？

线程自己独有的资源如下：

（1）程序计数器，表示线程自己正在执行的代码地址

（2）寄存器集合，包含线程当前自己的工作状态

（3）栈，每个线程自己独享的，用于存放局部变量，以及函数调用的上下文信息；理论上每个线程都有自己的栈，但是实际上线程可以修改别人的栈，虽然这样会导致 bug 而不被运行，线程之间并没有什么保护措施，一个线程有自己独有的内核栈和用户栈，设置内核栈的原因就是防止别的线程来访问系统调用时保存在栈中的各种数据

上述这些就是线程自己的上下文

用户级线程是什么？有什么优缺点？

（1）OS 无法感知用户级线程，一个用户级线程阻塞，整个进程全部阻塞（多对一模型）
（2）用户级线程本身之间线程管理很方便，利用高级语言函数即可

这里用户级线程其实就可以看作一整个进程的一个模块，或者一个对象，进程通过一个线程库方法来管理这些特殊的对象，其实这里完全可以将用户级线程理解成进程中不同的函数，由线程库负责这些函数的切换，那么很显然，当一个函数阻塞之后，整个进程都是阻塞的

但是在下面的 OS 看来，这些东西都是进程的代码，没有区别

内核级线程是什么？有什么优缺点？

（1）OS 可以识别内核级线程，因此当线程阻塞的时候可以调度别的线程执行，不会整个进程阻塞，并发能力强
（2）线程切换开销比较大

上图的用户级线程其实是早期的东西，随着 OS 的发展，OS 其实可以做到感知一个用户级线程，方法就是将用户级线程绑定一个内核级线程，OS 通过内核线程来对用户线程进行感知，因此 OS 可以通过内核级线程对用户级线程进行调度，只是要调度的时候需要绑定一个内核级线程

在运行的时候是直接运行用户级的线程，此时处于用户态，但是调度的时候需要 OS 绑定内核级线程进行调度，所以需要处理内核态，因此这种方式下线程的切换就比较复杂

线程的多对一模型是什么？

（1）线程管理效率高
（2）并发能力差，OS 只能感知一整个进程

这种情况下内核实际上还是只感知到一个线程，OS 认为还是一个单线程的进程，所以进程的调度还是用户区完成；同样的，当一个线程使用内核服务的时候被阻塞，其他的线程都无法执行

这种模型与纯用户级线程还是有点区别的，这种模式 OS 内核还是能感知到一个线程，而纯用户线程 OS 内核感知的就是一整个进程了

线程的一对一模型是什么？

（1）并发能力强
（2）线程管理代价高

这种跟上面常见的内核级实现是一样的，事实上内核级线程只有对应上用户级线程才有意义

多对多模型是什么？

（1）结合了一对一和多对一的优点

这种方式 OS 可以通过不同的内核级线程感知不同的用户级线程，所以这些对应不同内核级线程的用户级线程可以并行执行（多处理器）

此外，这里还是用户空间的线程库来管理这些用户线程，那么切换开销就比较少，是由用户状态下进行的

这种方式的缺点和多对一也类似，如果映射到同一个内核级线程的两个用户线程其中一个阻塞，那么这两个用户线程中另一个不需要 IO 的也被阻塞，当然另一个映射不同的内核线程的用户线程不会被阻塞

处理机调度基本概念

处理机的高级调度是指什么？

处理机的低级调度是什么？

一个作业通过高级调度调入内存，创建一个或者多个进程，这些进程处理就绪态，然后低级调度负责进程之间的调度，决定谁上 CPU 执行

高级调度处理的对象是作业相对于进程来说更上层一些

进程的上下文切换以及上下文是什么？

（1）上下文切换实际上就是进程切换的过程
（2）进程的上下文是指进程运行的所有状态信息

闲逛进程是什么？

即 idle 进程，每个 CPU 都有一个 idle 进程，idle 进程的优先级是最低的，当 CPU 一个进程都没有的话，CPU 就会运行 idle 进程，idle 进程并不参与进程调度

进程调度的时机有哪些？

主动放弃

（1）进程运行完毕，主动终止
（2）运行过程中发生异常
（3）发生时间请求阻塞（如进程主动进行系统调用访问 IO，发现 IO 没有输入数据，此时就会主动阻塞）

阻塞是进程的主动操作

被动放弃

（1）时间片用完
（2）被更高优先级的进程抢占
（3）更加紧急的事情需要处理（如外部中断）

不可调度

（1）处理中断过程中，这与中断嵌套不一样，中断过程中不可调度，因为中断程序逻辑上属于系统，并不属于任意某个进程，没有调度的概念
（2）内核临界区不可调度

fork () 函数

子进程是由父进程创建的进程，父进程通过调用 fork() 函数来创建一个子进程，子进程和父进程是两个不同的进程，他们的 PID 和 PCB 都是不同的，也不会共享虚拟地址空间；但是子进程会继承父进程对 OS 的某些全局资源，比如文件，管道，设备的访问权

当父进程调用 fork() 函数之后，子进程会得到一个父进程的虚拟地址空间的副本，即子进程会独立的有一个虚拟地址空间，但是这个地址空间的映射关系与父进程完全一样：


子进程和父进程此时拥有的代码段，数据段，堆，栈等完全相同

而当子进程试图修改某个页的数据的时候，就会触发这个页的复制，生成这个页的副本，这样父子进程就不会共享同一个物理页了：

这个称为写时复制技术，举一个例子如下：

#include <unistd.h>
#include <stdio.h>

int global = 10; // 全局变量（数据段）

int main() {
    int local = 20; // 局部变量（栈）
    printf("[main start] PID=%d\n", getpid());
    
    pid_t pid = fork();
    
    if (pid == 0) {
        printf("[child] global=%d local=%d\n", global, local);
        global = 100;
        local = 200;
        printf("[child modified] global=%d local=%d\n", global, local);
    } else {
        sleep(1); // 确保子进程先执行
        printf("[parent] global=%d local=%d\n", global, local);
    }
    
    return 0;
}

这里父进程调用了 fork() 函数之后就创建了一个子进程，这时子进程独立拥有一个虚拟地址空间，这个地址空间与父进程的地址空间映射到完全相同的代码段，数据段，堆，栈；

并且此时子进程和父进程同时从 fork () 之后的代码段开始执行，此时就是两个进程并发执行了，两者的执行顺序未知；不过代码段都是可读的，一般不会触发写时复制

当子进程修改变量的时候，就会触发写时复制，变量会实际复制到实际的物理空间中，然后子进程的虚拟地址空间的映射会发生改变，这样此时父进程和子进程其实对应的是物理空间中实际的两个不同的变量

运行结果如下所示：

[main start] PID=1234      // 父进程执行
[child] global=10 local=20 // 子进程初始值
[child modified] global=100 local=200
[parent] global=10 local=20 // 父进程值未变

exec () 函数

这个函数一般用于子进程换掉原有的父进程程序，让子进程对应一个全新的程序执行，这个函数的功能就是换掉当前进程执行的程序

具体来说，他会先摧毁原进程的虚拟地址空间的映射关系，然后将新的程序二进制装入内存，然后建立新的虚拟地址空间映射关系，此时进程就会对应全新的代码段，数据段，堆和栈

然后设置 PC 从新程序的入口开始执行

多对一模型：

其实就是通常是用户进程程序的线程库来完成线程的创建调度，当这个线程需要进行 IO 的时候就被阻塞，分配一个内核栈给它，这个过程可以理解是用户级线程与内核级线程的对应起来过程

进程的创建

除了第一个进程，操作系统中的进程均是由另一个进程创建的，创建进程的进程和被创建的进程互为父进程和子进程。父进程是在自己的内核空间创建子进程的。

在操作系统中，终端用户登录系统、作业调度、系统提供服务、用户程序的应用请求等都会引起进程的创建。操作系统创建一个新进程的过程如下：

  1. 为新进程分配唯一进程标识号（pid），并申请空白PCB（进程控制块）。若PCB申请失败，则创建失败。
  2. 为进程分配运行所需资源（如内存、文件、I/O设备、CPU时间等）。资源可能来自操作系统或父进程。若资源不足（如内存），进程进入“创建态”，阻塞父进程等待资源。
  3. 初始化PCB：
    • 初始化标志信息（如进程状态）。
    • 初始化处理机状态信息（如寄存器值）。
    • 初始化处理机控制信息（如调度参数）。
    • 设置进程优先级。
  4. 将新进程加入就绪队列，等待被调度运行。

这些创建过程是由一段原语执行的，称为创建原语，其特点就是执行的过程中不允许中断

进程的上下文切换

进程的上下文切换（Context Switching）是操作系统在多任务环境中实现进程调度的核心机制，指CPU从一个进程切换到另一个进程时，​保存当前进程的运行状态（上下文）并恢复新进程状态的过程

它涉及保存当前任务（例如：进程、线程）的状态（包括 CPU 寄存器、程序计数器、栈指针等），然后恢复下一个任务的状态，最终交给 CPU 执行。

主要的步骤如下：

1、保存当前任务的上下文：操作系统内核会保存当前任务的状态信息，包括 CPU 寄存器信息、程序计数器、堆栈指针等。这些信息通常会被保存在任务的进程控制块（PCB）中。

2、根据调度策略选择下一个任务：操作系统内核会根据调度算法选择一个合适的任务来执行。

3、恢复新任务的上下文，按照保存的信息：操作系统内核会加载新任务的状态信息，包括 CPU 寄存器、程序计数器等。这样，新任务就可以从上次中断的地方继续执行。

4、运行新任务：操作系统内核会将 CPU 的控制权交给新任务，新任务开始执行

各种调度的含义功能

中级调度

也就是内存调度，就是将暂时不能运行的进程调到外存去等待，此时这些进程的状态就称为挂起态，如果具备了运行的条件并且内存是空闲的，那么这个时候就由中级调度来决定将外存上的进程再次调入内存并修改状态为就绪态，并挂到就绪队列上等待

低级调度

也就是进程调度，它是根据某种算法来决定就绪队列上的哪个进程上处理机执行

高级调度

也就是作业调度，它决定将外存上处于后备队列的几个作业调入内存，创建进程，进程被创建之后首先处于创建态，然后系统会给其分配所需要的资源，然后修改其状态为就绪态

各个进程调度算法对于 IO 繁忙和 CPU 繁忙的进程的适用性（暂定，待继续总结）

IO 繁忙进程：这个进程大部分时间都在进行 IO 操作
CPU 繁忙进程：这个进程大部分时间都在进行 CPU 操作

FCFS 算法

不利于 IO 繁忙型进程，因为这类进程会大部分时间进行 IO 操作，只要 IO 操作它就会阻塞，然后放弃 CPU，OS 就会调度别的进程顶掉它；而相反的对于同时到达的 CPU 繁忙型进程它会一直占用，直到自己执行完毕；IO 繁忙型每次 IO 操作会被反复顶掉，因此周转时间就会很长

短作业优先算法

更有利于 IO 密集型进程，因为短作业优先的定义就是 CPU 更短的更优先调度，IO 密集型作业相对 CPU 密集型进程天然就在 CPU 上执行更短，所以更优先调度

高响应比优先算法

优先级调度算法

这个 IO 密集的进程优先级是更高的，因为这类进程可以先执行，然后阻塞，调度 CPU 密集的进程执行，这样 IO 和 CPU 就可以并行工作，省了很多时间

并且 IO 密集的进程往往与用户体验相关，所以应该被赋予更高的优先级

所以优先级调度算法更有利于 IO 密集进程

时间片轮转算法

这个调度算法对于任何进程都是一视同仁

短作业优先的平均周转时间和平均等待时间最少的理解

因为对于一串进程，只有执行时间更短的放在前面执行，总体的等待时间才会更少（可以用反证法证明）

这样平均周转时间是加上了等待时间的总执行时间除以进程个数，那当然就是最少的

同理平均等待时间也是最少的

当然抢占式的 SJF 的平均等待时间和平均周转时间更少

对用户临界资源不能同时访问的理解

对于单个 CPU 来说，这里的不能同时访问的意思其实就是并发访问，指的就是不能在一段时间中多个进程同时访问临界资源

具体来说，如果一个进程正在访问用户临界资源，它是可以并发的，即可以被阻塞暂停然后 CPU调度别的进程去 CPU 执行，但是这个别的进程不能访问这个临界资源，即对于单 CPU 的不能在一段时间内同时访问临界资源

不过，如果进程处于核心临界区就不能被打断调度了，因为处于核心临界区的进程访问的是内核资源，它可能就在访问进程的就绪队列，那它被打断调度别的进程，它还在临界区呢，临界资源还处于上锁状态呢，你进程调度需要访问就绪队列就不可能，无法完成调度，所以处于核心临界区的进程就无法被打断进行别的进程调度

34 关于线程切换的过程理解

I:
你线程负责的是一个进程不同功能模块，当然要切换不同的代码了，所以 PC 是一定要更新的

II:
线程切换会进行用户栈和核心栈（内核级线程）当然要更新基址寄存器的值；另外，线程自己对独有自己的上下文，包括：
（1）程序计数器，表示线程自己正在执行的代码地址

（2）寄存器集合，包含线程当前自己的工作状态

（3）栈，每个线程自己独享的，用于存放局部变量，以及函数调用的上下文信息；

所以当然会切换基址寄存器的值

III:
页表基址寄存器就是记录进程对应的页表的在内存中的首地址；这些线程共享进程的这个资源，所以不需要更新页表基址寄存器的值

IV:

当然不更新打开文件表

总的来说线程切换就是切换线程自己独自占有的资源，记住这个就行了

40 各个调度算法的系统开销分析

这里的系统开销包括，维护调度算法的数据结果，比如维护多个反馈队列等；计算优先级响应比等信息进行调度判断；以及更换进程带来的上下文切换开销等等

高响应比：需要实时更新每个进程的等待时间，然后计算每个进程的响应比，进行调度判断，这个开销不算小

多级反馈队列：需要维护多个反馈队列，需要更改维护每个进行的优先级，需要将进程进行队列调整，如果每个反馈队列是时间片轮转的话还有切换开销，多级反馈队列调度开销是比较大的

时间片轮转：需要频繁上下文切换，这个开销也不少

你显然 C 开销是最小的，它不用什么维护数据队列（多级反馈），也不用计算什么东西进行调度判断（高响应比，多级反馈队列），也不用频繁切换进程（时间片轮转）
