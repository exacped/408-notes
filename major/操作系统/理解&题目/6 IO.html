假脱机中的输入井和输出井是什么？分别有什么作用？

（1）这两个都是磁盘上开辟的两个存储区域
（2）输入井：收容 IO 设备输入的数据，数据流动： IO->内存->输入井->内存
（3）输出井：收容用户程序输出数据，数据流动：内存->输出井->内存->IO

假脱机中输入缓冲区和输出缓冲区是什么？他们在什么位置？

（1）都是内存中的区域
（2）一个负责外设之间数据交换，一个负责 CPU 和磁盘之间的数据交换

假脱机中的输入进程和输出进程分别有什么功能？

（1）输入进程（预输入进程），将数据从输入设备送到内存输入缓冲区再到输入井
（2）输出进程（缓输出进程），将数据输出井送到内存输出缓冲区再送到输出设备

假脱机中的井管理程序负责什么功能？

负责进程与输入和输出井的数据交换，OS 通过执行井管理程序来完成进程的数据放到输出井，或者将输入井中的数据读入到进程，当然这个过程都需要经过内存

假脱机打印机系统由哪些部分组成？分别表示什么功能？

（1）磁盘缓冲区，暂存所有用户的数据

设备驱动程序部分

设备驱动程序是什么？

其实就是控制外设的程序，它负责将上层软件发过来的命令和参数转换成硬件可以懂得具体要求，然后检查 IO 是否合法，然后利用控制器去控制硬件

设备驱动程序的功能有哪些？

（1）简而言之，所有与硬件直接相关的操作，都由驱动程序完成
（2）逻辑地址转换成物理地址
（3）了解 IO 设备状态
（4）发出 IO 命令
（5）响应中断请求，调度响应中断处理程序处理

设备驱动程序的特点有哪些？

设备驱动程序跟管理硬件非常紧密，但是不会直接管理硬件，而是通过中间的控制器来控制管理硬件

（1）实现在设备无关性软件和控制器之间通信的程序
（2）与 IO 硬件和控制方式联系紧密
（3）一部分必须由汇编语言编写
（4）允许可重入

设备驱动程序可重入的含义是什么？

（1）意思是可以允许多个进程同时安全调用设备驱动程序
（2）驱动程序的执行结果不会因为被打断而发生错误

一个完整的 IO 软件系统调度过程是什么？

如果一个用户想要读外设的内容，他会首先进行一个系统调用 read ()，然后到达了设备独立性软件层次，这个层次会解析用户的 IO 请求，同时设备独立性软件层会根据用户使用的逻辑号会映射到不同的物理设备，当然独立性软件部分还负责保护，分块，以及缓冲等功能，这里的分块是指独立性软件会将用户传递的数据（比如用户使用了write 调用）数据进行逻辑分块来对应磁盘中的一个块，比如 8 KB 的数据会被分成两个 4 KB 的逻辑块（磁盘一个块是 4 KB）

设备独立性软件解析完这个命令之后继续往下传递，设备驱动程序会将上层传下的抽象的 IO 请求进一步转化成硬件看懂的命令，比如将用户要读的磁盘的地址转化成切实的哪个盘面，哪个磁道等等，总的来说就是设备驱动程序会将上层命令解析成硬件（IO 接口）可以看懂的命令

驱动程序会继续将命令往下传递，具体来说，驱动程序会调动中断处理程序

再到中断处理程序，这个部分严格来说与设备驱动程序很难分开，以中断方式控制传递数据为例，进行中断响应，切换 CPU 状态，然后保护现场之后，通过一些特殊的 IO 指令控制控制器，开启 IO 让其准备数据，并阻塞当前进程，调度别的进程执行之后，IO 和 CPU 并行工作，当外设准备好了一个数据之后就触发中断，由驱动程序收到中断信号，并调用中断服务程序控制 IO 接口读取一个数据，往上递交，然后中断返回，CPU 继续执行被打断的进程，IO 继续准备数据

磁盘块和磁盘扇区的区别是什么？

（1）磁盘扇区是磁盘实际读写的时候的基本单位
（2）磁盘块是上层操作系统抽象的基本单位，也可以说是上层文件系统操作文件的最小单位







在上层文件系统，磁盘是按照磁盘块组织起来的，一个磁盘块可能包含多个实际的物理扇区，哪怕一个文件大小小于一个扇区，在逻辑层面也会将整个磁盘块分配给这个文件，即将相邻的多个扇区分配给这个文件

不过在更下层的物理层面，如果文件的大小小于一个扇区，虽然可能相邻的扇区在逻辑上按照磁盘块大小分配给了这个文件，但是驱动程序可能也只会读写一个扇区将文件放入磁盘，因此扇区是磁盘的基本读写单位，而磁盘块（或者说簇）是文件系统操作文件的最小单位

磁盘的基本读写单位是什么？这里以扇区为基本读写单位是什么含义？

（1）基本读写单位是扇区
（2）基本读写单位的含义就是，哪怕要读取的数据小于一个扇区，此时读也会完整读整个扇区，而不是单纯读扇区中的数据
（3）上层文件系统按照逻辑上的磁盘块来操作分配文件，一个磁盘块可能对应多个扇区，哪怕一个文件大小小于一个扇区，OS 也会直接将整个磁盘块分配给这个文件，即文件系统操作的最小单位就是磁盘块；但是在实际读的时候，底层磁盘实际上只会读这个文件所占的一个扇区，即磁盘基本读写单位是扇区

扇区是磁盘最小的物理存储单元，是磁头从磁盘中读取数据的最小单位（一般 512 B），即磁头每次从磁盘中读取数据，都是一个扇区一个扇区读的

但是这 2 KB 的数据继续往下，实际驱动程序知道这 2 KB 只占了一个扇区，所以它其实只会操作一个扇区进行写入，即磁盘的基本读写单位是一个扇区，哪怕写入的数据小于一个扇区

以上就是逻辑磁盘块与扇区的区别的联系

分页式请求地址拼接与分段式地址相加的区别

分页式

虚拟存储空间分页，实际物理空间也分页

虚拟地址分为页号 + 页内偏移
物理地址也分为页框号 + 页内偏移

页表记录页号和页框号的对应关系

地址转换的时候直接将虚拟地址中的页号替换为页框号，页内偏移保持不变

这是因为将页调入内存的时候是整个页调入的，某个页中的存储单元在页中的偏移在调入某个页框之后偏移不变

这里的正确性就在于，分页式的各个地址级别所包含的存储单元个数是 2 的幂次方，因此连续增长的存储单元，存储单元的十进制编号，写成二进制形式，二进制对应的比特位数就直接是相应的页框号，以及页内偏移

分段式

虚拟存储空间分段，实际物理空间不划分

虚拟地址分为段号 + 段内偏移
物理地址不划分

段表记录段号和段的内存起始地址以及段长

地址转换的时候通过段内偏移 + 段的起始地址得到物理地址，而不是拼接

因为实际物理内存完全没有段的概念，都没有段号，并且虚拟存储空间中的每个段的长度还不一样，包含的存储单元个数也不一定是 2 的幂次方，不满足二进制的对应关系，所以不能简单进行拼接，拼接毫无意义

总结

（1）对于连续递增的存储单元，对其进行十进制编号递增才是本质，按照通法计算它每个级别的地址是什么才是本质
（2）对于包含了 2 的次幂个数的地址排布，将每个存储单元十进制编号写成二进制才有意义，此时可以通过观察每级地址对应的 bit 位直接得到编号
（3）对于不是包含了 2 的次幂个数的地址排布，将每个存储单元十进制编号写成二进制没有意义，存储单元递增与每一级地址递增不符合对应二进制增长规律

单缓冲传输和处理连续两个数据的时间是多少？

缓存区每次只能执行一个动作，要么接收输入，要么传送，不能传送和输入同时进行

工作区每次只能执行一个动作，要么接收输入，要么执行，不能执行和接收输入同时进行

工作区的执行处理和 IO 设备输入到缓存是可以并行的

第一个阶段：IO 向缓存输入数据，时间为 T，这个时间不能省

第二个阶段：缓存向工作区输入数据，此时 IO 不能向缓存输入，所以必须花费 M 时间，不能省略

第三个阶段：工作区处理数据，以及 IO 向缓存区输入数据，这个可以并行，但是无论哪个先完成，都必须等待另外一个完成，比如 C 的时间大于 T，那么 IO 输入到缓存花费 T 先完成，但是工作区还在处理数据，此时 IO 无法向缓存继续输入数据，缓存也无法输入数据到工作区；同理如果 T > C 也是这样，工作区的数据处理完了之后必须等待 IO 输入数据到缓存区才行，因此这个阶段的时间必须是 Max (C, T），第三阶段结束，缓存区有了第二个数据

第四个阶段：缓存区输入数据到工作区，M 时间

第五个阶段：工作区处理，C 时间

所以连续处理两个数据的时间就是 T + M + Mac (C, T) + M + C

对于中断方式的 IO 控制，中断服务程序会先将数据读入到 CPU 的通用寄存器，然后再将数据放入到内核缓冲区，此时中断服务例程结束

缓冲池概念以及引入缓冲池的原因

缓冲池其实是由很多的内存缓冲块构成的，这些缓冲块是由操作系统来分配和管理的，缓冲池与通常意义的缓冲区的区别在于，缓冲区一般都是一个进程独有的，为单独一个进程开辟的一块区域，而缓冲池则是由 OS 软件来分配给各个进程缓冲块的一片共享的区域

对于单缓冲或者双缓冲或者循环缓冲，他们其实只针对单个特定的任务而创建的缓冲；如果这个系统是一个多任务系统，那么每个任务都会分配一个缓冲，这样会导致缓冲区过多；于是这样就引入了缓冲池，OS 划分了一片共享的内存区域，每个任务按序索取里面的内存块作为缓冲即可

缓冲区是一定放在内存的，只有放在内存才能让 CPU 取数据加速，如果缓冲区放在外存，那完全毫无意义

双缓冲区在双向传送设备中的意义

双缓冲区，一个缓冲区用于接收数据，一个缓冲区用于发送数据

比如网卡设备，他的缓冲区就设置在内存，一个发送缓冲区和一个接收缓冲区

当 CPU 处理好了数据之后就把数据放到发送缓冲区即可，CPU 就可以转头执行别的操作，等到网卡有空取走数据即可；同理当网卡受到数据时先放到接收缓冲区中，然后 CPU 有空取走即可

这样 CPU 与网卡之间不仅仅可以并行工作，实现数据的并行传输，同时 CPU 取数据从内存中取，也大大减少了 IO 等待时间，

设备的一些分配方式（静态分配和动态分配）

独享分配：只能将设备分配给一个进程让其独占，等到进程完成自己的操作才释放设备

共享分配：比如磁盘的分配，可以有多个进程在同一段时间并发访问，进程并不独占设备，在一段时间内通过分时来进行并发访问设备

虚拟分配：将一台物理设备变成几个逻辑设备，然后分配给进程

静态分配：也就是固定的把某个设备分配给某个进程，在进程完成它的任务之前都不会释放这个设备或者分配给其他的进程，因此对于独占设备往往采用的就是静态分配（其实就是独享分配）

动态分配：对于磁盘来说，进程 A 的磁道请求可能是 100 200 500，进程 B 的磁道请求可能是 300 150 160；对于磁盘的调度算法来说，它可能先响应 100 的磁道请求，然后再响应 150 的磁道请求，这样磁盘其实是在两个进程请求之间轮转，这个就是动态分配；而静态分配则是先将 A 进程的请求 100 200 500 处理完再去处理 B 的请求；对于磁盘这样的共享设备往往就采用动态分配方式

计算机中的编址规律

这里以一个含有 8 个物理块，每个物理块中有 8 个存储单元的内存为例

他的地址格式是 AAA BBB

AAA 表示物理块号，BBB 表示块内的存储单元号

5 缓冲池的概念

缓冲池其实是由很多的内存缓冲块构成的，这些缓冲块是由操作系统来分配和管理的，缓冲池与通常意义的缓冲区的区别在于，缓冲区一般都是一个进程独有的，为单独一个进程开辟的一块区域，而缓冲池则是由 OS 软件来分配给各个进程缓冲块的一片共享的区域，所以它这里还是需要在硬件基础之上使用软件的进行管理的

CD 都需要软件程序干活来进行控制

6 整个 DMA 的传输过程

首先用户会执行一个 read () 函数，然后进入内核，进入内核之后会执行一段例程，这个时候当前进程其实并没有被阻塞，仍然是在用户进程的大背景下，只不过是换到了内核中去执行另外一个函数，但是实际上还是在执行用户进程的一部分程序，只不过这部分程序在内核中，这个例程只不过是一段代码

由于是 DMA 方式，这个例程函数会继续调用一个预处理程序，预处理程序实际上是设备驱动程序中关于预处理的一部分，CPU 通过执行预处理程序来进行 DMA 的预处理过程

然后当数据传输完毕之后，DMA 发起中断，让 CPU 去执行中断服务程序来进行后处理，这里的后处理并不是最开始发起 IO 的进程程序，而是系统中用于处理 DMA 中断的中断服务程序（并且此时这个发起 IO 的进程还是处于阻塞状态）
