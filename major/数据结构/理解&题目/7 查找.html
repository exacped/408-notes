7 查找

1.2 万字约 28 分钟2026-07-29

理解

查找效率，查找次数，平均查找次数，查找长度

查找次数就是查找长度

平均查找次数是所有元素查找次数的平均值

查找次数和平均查找次数可以用来衡量查找效率

平均查找长度与查找操作复杂度的关系

查找操作的复杂度是最多查找长度数量级，不是平均查找长度的数量级

对于一个二分查找判定树，二叉排序树，平衡二叉排序树，红黑树，其最多查找次数都是与树的高度一致的

二分查找相关的效率分析

二分查找判定树的树高是 ⌈log2​(n+1)⌉

二分查找最坏的查找次数是树高，即 ⌈log2​(n+1)⌉

二分查找的时间复杂度是树高的量级，即 O(log2​n)

等概率的n 个结点的二分查找的平均查找次数大约是 log2​(n+1)−1，其量级就是 O(log2​n)

当然具体一颗树的平均查找次数还是按照普通的平均查找次数计算过程计算

二叉排序树相关的效率分析

二叉排序树的树高不固定，最好情况下的树高是 ⌊log2​n⌋+1，即 ⌈log2​(n+1)⌉， 最坏情况下的树高是 n

最好情况下的最多查找次数就是 ⌊log2​n⌋+1，最坏情况下的最多查找次数就是 n

最好情况下的查找复杂度就是 O(log2​n) 级别，最坏情况下的查找复杂度就是 O(n) 级别

最好情况下的平均查找次数就是 O(log2​n) 级别，最坏情况下的平均查找次数就是 O(n) 级别

平衡二叉排序树相关的效率分析

n 个结点的平衡二叉树的树高的数量级是 O(log2​n)

所以其最多查找次数的数量级就是 O(log2​n)

所以查找复杂度也是 O(log2​n) 的级别

平均查找长度也是 O(log2​n) 的级别（记住即可）

平衡二叉树高度为 h 的最少结点个数公式推导

要想平衡二叉树的结点最少，其一定是根结点的两个子树的高度差为 1 的情况

因为假设根结点的两个子树的高度一样，此时结点个数最少，那么我们可以在其中一个子树中拿掉一些结点使其高度减一，此时仍然是平衡二叉树，但是结点数更少，所以矛盾

假设此时树的高度是 h，最少结点个数是 ah​，那么这个根结点的子树，必然有一个高度是 h - 1，一个高度是 h - 2

我们让这两个子树的结点个数也尽可能少，所以得到递推公式：

ah​=ah−1​+ah−2​+1

二叉排序树，AVL 树，RBT 的查找，插入，删除操作的区别

二叉排序树，AVL 树，RBT 的查找，插入，删除的基本过程都是一样的

但是这些基本操作的时间复杂度不一定一样，因为这些操作与树高相关，对于二叉排序树，其树高最坏情况下是 n，所以复杂度会更高一些

不同指出在于 AVL 树在插入和删除之后需要进行调整使得满足 AVL 树定义

红黑树在插入和删除之后也要进行调整使得满足红黑树的定义

红黑树相关的效率分析

n 个结点的红黑树的高度 h 满足 h≤2log2​(n+1)

所以查找操作复杂度就是 O(log2​n) 级别，平均查找长度也必然小于 O(log2​n) 的级别

删除操作复杂度也是 O(log2​n) 级别（基本不考）

红黑树的路径长度性质

（1）红黑树有叶结点，并且是黑色的，是外部结点，即除了关键字之外的结点

（2）红黑树内部结点 A到叶结点的路径长度，就是经过的边的个数，也是这个路径上除了结点 A 本身的结点个数

（3）红黑树定义必须满足内部结点到任意叶结点经过的黑色结点个数相等（包不包括当前节点都无所谓）

（4）红黑树的红色结点不能相邻出现

根据 （3）（4），从内部结点到叶结点的路径上，红色结点最多的情况一定是交叉出现的这种情况，一直到叶结点是黑色，要么是：红黑红黑红黑，要么是：黑红黑红黑

（5）所以从内部结点到任意叶结点的路径上的红色结点个数必然 <= 黑结点的个数

根据（3）任意内部结点到任意叶结点的最长路径上的黑色结点个数是 n ，那么最短路径上的黑色结点个数也是 n

最短路径，那就是完全没有红色结点，就剩下 n 个黑节点个数，也就是经过的边数，即长度至少是 n

最长路径黑色结点为 n，剩下的是红色结点，红色最多是 n，所以最长路径结点个数（除了结点自身）是 2 n，所以路径长度最长是 2 n

（6）因此每个内部结点到任意叶结点的路径，最长路径不会超过最短路径的两倍

二分查找判定树，二叉排序树，AVL 树，RBT 的树高相关结论总结

二分查找判定树的树高就是 ⌈log2​(n+1)⌉，是一个定值

二叉排序树的树高最好情况下的树高是 ⌊log2​n⌋+1，即 ⌈log2​(n+1)⌉，最坏情况下的树高是 n

AVL 树的树高为 h，其对应的最多结点个数是满二叉树的情况，其对应的最少结点个数有一个递推公式；但是不管怎样，其树高是 O(log2​n) 的数量级

RBT 的树高为 h，则 h≤2log2​(n+1)，也是一个 O(log2​n) 的数量级

B 树和 B+树定义区别

m 阶B 树：

（1）除了根结点之外的其他结点（不包括叶结点）的关键字个数是 ⌈2m​⌉−1≤k≤m−1，根结点的关键字个数是 1≤k≤m−1

（2）除了根结点之外的其他结点（不包括叶结点）的分支个数是 ⌈2m​⌉≤k≤m，根结点的分支个数是 2≤k≤m，结点的分支个数是关键字个数加 1，结点的分支个数最多是 m 个，称为 m 阶 b 树

（3）B 树是某个结点的关键字左右指针指向下一层结点，所以 B 树的某个结点的分支个数比关键字个数大 1

（4）B 树的叶结点全部出现在同一层次上并且不带信息

（5）B 树的根结点至少有两个子树（两个分支）

m 阶 B+树

（1）除了根结点之外的其他结点（包括叶结点）的关键字个数是 ⌈2m​⌉≤k≤m，根结点的关键字个数是 1≤k≤m

（2）除了根结点之外的其他结点（包括叶结点）的分支个数是 ⌈2m​⌉≤k≤m，根结点的分支个数是 1≤k≤m，结点的分支个数与关键字的个数相等，结点的分支个数最多是 m 个，称为 m 阶 B+树

（3）B+树是某个结点本身指针指向下一层结点，所以 B+树的某个结点的分支个数与关键字个数一样

（4）B+树的叶结点全部出现在同一层上，并且包含了全部的关键字，分支结点的关键字也会在叶结点中

（5）B+树的非叶子根结点（叶子根结点就是只有一个结点，这个结点既是根结点又是叶子结点），一定有两个子树（两个分支）

所以一共读了 h 次，写了 2 h + 1 次，一共 3 h + 1 次

20 B 树和 B+树当作文件索引的区别 + 顺序查找和随机查找的理解

顺序查找是指：从第一个关键字开始，逐个与给定的关键字进行比较，不管结果如何，查找的元素始终是下一个相邻的关键字

随机查找是指：比较完关键字之后，下一次查找的关键字的位置没有统一的规律，而是根据比较结果而定，可能是左边的元素，可能是右边的元素

事实上，B+树更适合做数据库的索引和文件索引，因为 B+树只有最下面的叶子结点会记录关键字对应的信息的地址信息，而 B 树的每个结点都会记录关键字对应的信息的地址

这就导致同样一个磁盘块，B+树可以保存的结点个数就更多，比如同样多的关键字个数，B+树需要的磁盘块更少，这样磁盘块构成的树形结构就更矮一些

那 CPU 在查找关键字的时候就可以通过读取更少的磁盘块来找到关键字，IO 操作时间上就更少，所以 B+树比 B 树更适合做文件及数据库的索引

25 堆积的概念

堆积就是大量的元素在相邻的位置聚集起来，比如线性探测就非常容易引起堆积现象，因为一旦冲突就直接放到下一个位置了

这道题目的堆积就是指一堆元素总是放在相邻的位置处，这样可以是同义词（映射到同一个位置的关键字）冲突导致，冲突之后往后移动一位，出现堆积；也可以是非同义词（映射到不同位置的关键字）冲突导致，因为别的关键字因为跟同义词冲突往后移动一位之后将其位置给占了，比如取模之后为 i 的元素 A，i 位置有了 B，那就只能在 i + 1 处存放，但是对于其一个非同义词 C，其摸是 i + 1，映射到 i + 1 处，也出现了冲突，于是 C 只能放在 i + 2 处，这样也出现了堆积
