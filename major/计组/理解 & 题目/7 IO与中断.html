程序查询方式的理解和一个例题

程序查询方式的 IO 接口基本结构如下所示：

这里以 CPU 从外设读一个数据为例来说明数据传送的过程

（1）CPU 执行 IO 指令向状态寄存器中写入启动外设控制命令，比如 OUT 指令，具体来说，CPU 通过地址线指明此时的控制命令要输出的 IO 端口地址，然后通过控制线指明 CPU 执行写操作，接着这个启动命令通过数据线写入到状态寄存器中；

（2）IO 接口中的控制逻辑将状态控制寄存器（IO 端口）中的启动命令发送给外设，外设开始启动，准备数据；接着控制逻辑将状态寄存器设置为外设忙的信号，这个状态信息会覆盖控 IO 端口原来的控制信息，不过这个控制信息已经发出去了，不用再保存

之后 CPU 通过不断的执行 IN 指令来读取状态寄存器端口中的状态，来看看 IO 是否准备好了数据

（3）外设准备好一个数据，通过数据线写入到 IO 接口中的数据缓存寄存器端口中

（4）外设准备好了数据之后通过状态线反馈给 IO 控制逻辑，IO 控制逻辑将状态寄存器设置为 ready

（5）CPU 通过读取状态端口寄存器发现数据准备完毕，于是再通过 IN 指令从数据缓存寄存器中取走数据

以上就是 CPU 通过程序查询方式从外设取走一个数据的具体过程

在 CPU 查询 IO 接口中的状态端口的时候有两种方式，一种是 CPU 完全停下现在自己正在做的事情，一直反复的查询这个端口，这个方式称为独占查询，CPU 将所有的时间都用来 IO 操作；

另一种方式是定时查询，即 CPU 会隔一段时间查询一次 IO 端口，在这些时间间隔 CPU 会去干别的事情

这道题目中，一次查询是 400 个时钟周期，处理器 1 s 有 500 M 个时钟周期

这道题目是定时查询方式，即 CPU 会隔一段时间查询一次，其他的时间执行其他的任务

内部异常与外部中断

异常是 CPU 内部的引起的中断事件，其包括故障，自陷，终止

外部中断就是外部 IO 向 CPU 发送的硬件中断请求（如鼠标点击和键盘输入）

在袁书的教材中，一般用异常指 CPU 的内部异常，中断指外部中断

中断控制器的基本结构

中断控制器本身也是一个 IO 设备，CPU 可以访问其 IO 接口配置其功能，比如设置其中断屏蔽字寄存器 IMR，它也被称为可编程中断控制器，其基本结构如下所示：

下面依次说明这个中断控制器的各个结构

IRR，中断请求寄存器

它用于暂存每个外部设备的中断请求，IRR 的每一位对应一个外部设备，其值为 1 的时候表示外部设备发出了中断请求，IRR 中的内容又称为中断字，中断处理的时候就通过中断字来确定中断源，从而转到对应的中断处理程序

IMR，中断屏蔽字寄存器

IMR 的每一位对应一个设备中断源，中断源为 1 的时候表示屏蔽这个中断源发送的中断请求，为 0 的时候表示允许发送

对于不同的外部设备，他们由 CPU 设置不同的中断屏蔽字，当执行他们的中断服务程序的时候会将中断屏蔽字写入到 IMR 中，此时所有其他设备发送的中断请求都会先与自己的中断屏蔽字的每一位进行一个与操作，没有被屏蔽的中断请求再送到中断响应电路中进行请求优先级排序

中断屏蔽字可以动态的改变中断优先级；但是中断屏蔽字只有在 CPU 运行服务程序的时候才能设置，当 CPU 执行主程序的时候仍然采用的是中断响应的优先级

优先级排队电路

这个优先级排队电路的输入是多个通过了屏蔽的中断请求信号，输出是优先级最高的中断编号和中断请求信号

中断编号通过数据总线 DBUS 反馈给 CPU，而中断请求号 INTR 则通过控制总线 CBUS 传输给 CPU，同时通过控制总线接收来自 CPU 的中断应答信号 INTA

ISR，中断服务寄存器

它用来存放多重中断中所有得到中断响应但是中断服务程序还没有结束的中断请求

一般来说，在多重中断中，低响应优先级的中断可以设置屏蔽字来屏蔽掉高响应优先级的中断，从而避免自己被打断嵌套；但是如果此时是一个高响应优先级的中断服务在执行，低优先级哪怕没有被屏蔽，它也不能去打断高优先级的中断服务；即普通的屏蔽模式下，只能是高响应优先级去打断嵌套低响应优先级中断

一个新的中断请求通过了屏蔽电路，它会在排队电路中不仅仅与别的通过了屏蔽的请求排队，还要与当前的 ISR 中的中断请求排队，从而决定这个中断请求是否被送给 CPU，只有一个通过了屏蔽，并且响应优先级最高，并且比当前 ISR 中的中断请求的优先级还高的中断请求才会被送给 CPU，才会打断当前的服务程序，进行中断嵌套

（2）中断响应

在中断响应中 CPU 主要执行三个操作，这三个操作是由硬件自动执行的，就好像有默认的指令一样，所以称为隐指令：

i 关中断

设置 IF = 0 关中断，这一步是 CPU 为例避免在后面保存信息的时候被别的中断过来打断导致信息丢失中断除了完了无法返回

ii 保护程序断点

将当前程序计数器 PC 和当前程序状态字 PSW 入栈保存，这是为了能够在中断执行完毕之后可以返回；如果是外部中断，保存的是当前执行程序指令的下一条地址；如果是内部异常，中断就是由当前指令引起的，所以保存的就是当前指令的地址，中断处理完毕之后要重新执行当前指令

（5）恢复现场

这一步与保护现场是逆操作，将保存的各个寄存器的值出栈恢复

此时 CPU 设置 IF 为 1，允许 CPU 响应新的中断请求

（7）中断返回

DMA 方式与中断方式传输数据的区别

（1）在传输数据的过程中中断技术是 CPU 执行程序来进行数据传输，所以涉及到原来程序的现场保护问题；而 DMA 是硬件传输数据，所以 DMA 在传输数据中不涉及现场保护

（2）CPU 对中断请求的响应是在指令执行结束之后（指令执行周期结束后，并不是指令周期之后）；而 CPU 对 DMA 请求的响应则是在指令的机器周期结束后

（3）中断过程传输数据需要 CPU 的干预，依靠 CPU 执行程序传输，占用的是 CPU 时间；DMA 方式则是依靠硬件传输数据，不占用 CPU 时间

（4）DAM 方式只能用于数据传送，中断方式还可以用于进行异常的处理
